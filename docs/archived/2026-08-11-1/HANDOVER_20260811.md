## 1. 项目背景

### 1.1 业务问题

日用陶瓷在热震过程中（高温骤冷）产生裂纹，影响产品合格率。需要**实时预测**：
- 裂纹**位置** (x, y)
- 裂纹**尺寸** (l, w)
- **置信度** (conf)
- **裂纹密度** (density)

### 1.2 物理约束（设计动机）

- 裂纹密度随温度下降**单调递增**（格里菲斯断裂准则）
- 裂纹**不可逆**（一旦出现不会消失）
- 裂纹位置与**应力集中区域**强相关

### 1.3 输入输出

- **输入**：1D 温度时序（300 步，单变量）+ 2D 温度场+应力场图像（512×512×2 通道）
- **输出**：检测向量 `[x, y, l, w, conf, density]`（6 维）

## 2. 模型架构

### 2.1 5 个变体清单

| # | 变体 | 2D 骨干 | 检测头 | 1D 时序骨干 | 显存 | 实验定位 |
|---|------|---------|--------|-------------|------|----------|
| 1 | `resnet18` | ResNet-18 | 单点向量 | CNN+Attention | ~2GB | 基准基线 |
| 2 | `vit_yolo` | ViT-Small | YOLO 网格 | CNN+Attention | ~3GB | 全局注意力 vs 局部 |
| 3 | `swin_yolo` | Swin-Tiny | YOLO 网格 | CNN+Attention | ~4GB | **推荐基线** |
| 4 | `detr` | ResNet-18 + Transformer | DETR | CNN+Attention | ~5GB | 端到端全局 |
| 5 | `swin_yolo_patchtst` | Swin-Tiny | YOLO 网格 | PatchTST | ~4GB | 时序骨干升级 |

### 2.2 设计哲学

- **模块化可插拔**：每个组件（2D 骨干 / 1D 骨干 / 检测头 / 融合 / 注意力）可独立替换
- **控制变量法**：14 任务（5 基线 + 5 消融 + 3 组合 + 1 SOTA 长训）
- **subdir 是实验分组不是架构**（baseline/gated/coord/staged/triple/cutmix）
- **DETR 慢收敛但理论精度高**，需 150 epoch 完整训练

### 2.3 关键技术参数

| 项 | 值 | 备注 |
|---|---|---|
| 优化器 | AdamW (lr=1e-4, weight_decay=0.01) | **YOLO/DETR 必须 ≤1e-4**（1e-3 必 NaN） |
| 调度器 | CosineAnnealingLR (T_max=epochs, eta_min=1e-6) | |
| 早停 | patience=30, min_delta=1e-4 | |
| FP16 | 默认开启 | 8.5GB 显存下能跑 batch=8 |
| 配置签名 | 14 字段 | DETR 额外含 image_size |
| 数据集 | 6 个参数化扫描文件夹 | 4251 train / 1063 test |

## 6. 关键决策（不要再问为什么这么设计）

1. **5 个变体**：resnet18 / swin_yolo / vit_yolo / detr / swin_yolo_patchtst
2. **subdir 是实验分组不是架构**（baseline/gated/coord/staged/triple/cutmix）
3. **A4_long 与 A4 共享** `detr/baseline/`，**通过 task_id 区分**
4. **YOLO/DETR 必须 LR≤1e-4**（1e-3 必 NaN，已验证 epoch 18 NaN）
5. **resnet18 是所有优化的 baseline**（B 组基于它消融）
6. **DETR 150 epoch 长训**（v4.6.10 修复续训 bug 后跑通）
7. **14 个任务设计哲学**：5 基线 + 5 单变量消融 + 3 多变量组合 + 1 SOTA 长训
8. **配置签名校验 14 字段**（含 DETR 专用 `image_size`）
9. **CSV 按 task_id 分文件**（不引入 DB，append 模式）
10. **Windows GBK 编码兼容**（`sys.stdout.reconfigure(encoding='utf-8')` 在脚本入口）
11. **不写专利**（用户明确"我们只需要管模型的构建与训练部分"）
12. **会议要求"先 SOTA 后消融"**（不要在没有 SOTA 之前做意义不大的消融）

## 7. 踩过的坑（避免重复）

| 坑 | 教训 |
|---|------|
| ASCII 框图（box-drawing 字符）在 Markdown 渲染错位 | 用 mermaid 流程图（GitHub 渲染支持） |
| PowerShell `Out-File` 默认 CRLF 把多行 commit message 压成一行 | amend commit message 用 `git commit --amend -F <file>`，文件**必须 LF**（用 Python 写） |
| PowerShell `-m ""` 空字符串参数解析错误 | 用 `-F <file>` 替代 |
| Windows GBK 不能输出 `\u2588 \u2591` 块字符 | 进度条改 ASCII (`#`/`-`) + `sys.stdout.reconfigure(encoding='utf-8')` |
| 续训 bug：`train_model` for 循环硬编码 `range(config['epochs'])` | 必须新增 `start_epoch=0` 参数 + `range(start_epoch, config['epochs'])` |
| `last_checkpoint_path` 推断只处理 `_best.pt` | 扩展支持 `_best/_last/其他` 三种结尾 |
| `best_loss = float('inf')` 不继承历史 | 透传 `best_loss=best_metric` |
| LR=1e-3 在 YOLO/DETR 必 NaN | 必须 ≤1e-4 |
| `is_complete` 误判未完成 | `_print_progress_table` 改用 `is_complete` 单字段判断 |
| emoji `\U00002714` GBK 崩溃 | v4.6.1 已替换 `[OK] [FAIL]`，但其他 Unicode 块字符漏了，v4.6.10 修复 |
| bash subcommand 报"$VAR = ..." 拒绝 | PowerShell 改用 `[System.IO.File]::ReadAllBytes` 验证文件 |
| 用 `Remove-Item` 删除文件被权限拦截 | 用 `Move-Item` 到 `checkpoints/backup/` 替代 |
| `git commit` 偷懒只写一句话 | 用户两次纠正，详细 body + `Co-Authored-By: MiniMax-M3` |
