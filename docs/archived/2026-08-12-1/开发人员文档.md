## 一、项目概述

### 1.1 物理背景

日用陶瓷在热震过程中产生裂纹，需要预测裂纹的位置、尺寸和密度。

**物理约束**：
- 裂纹密度随温度下降单调递增（格里菲斯断裂准则）
- 裂纹不可逆
- 裂纹位置与应力集中区域相关

### 1.2 输入输出

| 任务模式 | 输入 | 输出 |
|----------|------|------|
| `detection` | 温度时序 + 图像 | [x, y, l, w, conf, density] |
| `segmentation` | 温度时序 + 图像 | 256×256 二值掩膜 |
| `multitask` | 温度时序 + 图像 | 检测向量 + 分割掩膜 |

### 1.3 模型变体

| 变体 | 架构 | 显存占用 | 说明 |
|------|------|----------|------|
| `resnet18` | ResNet-18 + Cross-Attention | ~2GB | 轻量基线，稳定快速 |
| `swin_yolo` | Swin-Tiny + YOLO-FPN + Cross-Attention | ~4GB | 空间网格定位，图像注意力 |
| `vit_yolo` | ViT-Small + YOLO-FPN + Cross-Attention | ~3GB | 全局自注意力，轻量 |
| `swin_yolo_patchtst` | Swin-Tiny + YOLO-FPN + PatchTST | ~4GB | YOLO + PatchTST时序骨干 |
| `detr` | ResNet-18 + Transformer + Cross-Attention | ~5GB | 全局上下文，100个Object Queries |

## 四、模型架构详解

### 4.1 基础模型：PETSNetMultimodal (resnet18)

```
输入
├── 1D分支：(B, 300) 温度序列
│   ├── Micro1DCNN → 局部特征 (32维)
│   ├── Macro1DCNN → 全局趋势 (32维)
│   ├── Multi-Head Self-Attention → 通道融合
│   └── 输出：64维向量
│
└── 2D分支：(B, 2, H, W) 温度场+应力场
    ├── ResNet-18（ImageNet预训练）
    │   └── 输出：(B, 512, H', W')
    └── GlobalAvgPool → (B, 512) 向量

融合：CrossAttentionFusion
输出：MultiTaskHead → (B, 6) [x, y, l, w, conf, density]
```

### 4.2 SwinYOLOFPN (swin_yolo)

```
输入
├── 1D分支：同 PETSNetMultimodal → 64维
│
└── 2D分支：(B, 2, 512, 512)
    ├── SwinBackbone2D（timm Swin-Tiny，img_size=512）
    │   └── 输出多尺度特征
    ├── yolo_proj：Conv2d(768→256) + BN + ReLU
    └── YOLOFPNHead → (B, 6, 16, 16)

训练模式：返回 (B, 256, 6) 完整网格预测
推理模式：取最高conf → CrossAttentionFusion → MultiTaskHead
```

### 4.3 ViTYOLOFPN (vit_yolo)

```
输入
├── 1D分支：TemporalFeatureExtractor → 64维
│
└── 2D分支：(B, 2, 任意尺寸)
    ├── input_resize：Conv2d(2→3, kernel_size=1) + BN + ReLU
    ├── ViTYOLOBackbone2D（timm vit_small_patch16_224）
    │   └── 输出：(B, 256, 7, 7)（骨干输出已为256通道）
    ├── interp：Resize到 (16, 16)
    ├── fpn：Conv2d(256→256, kernel_size=3) + BN + ReLU
    └── YOLOFPNHead → (B, 256, 6)

训练模式：返回 (B, G², 6) 完整网格预测（G² = actual_grid_size²）
推理模式：取最高conf → fusion → output_head → (B, 6)
```

**actual_grid_size**：通过 `max(16, (image_size//32 // 4) * 4)` 动态计算（至少16）。

### 4.4 SwinYOLOFPNWithPatchTST (swin_yolo_patchtst)

与 SwinYOLOFPN 相同架构，但 1D 分支使用 `PatchTST1D` 替代 `TemporalFeatureExtractor`。支持 triple_channel 三通道输入。

### 4.5 DETRStyle (detr)

```
输入
├── 1D分支：TemporalFeatureExtractor → 64维
│
└── 2D分支：(B, 2, 256, 256)
    ├── ResNet18Backbone2D（启用 set_spatial_output=True）
    │   └── 输出：(B, 512, 8, 8)
    ├── TransformerEncoder（6层）
    ├── DETRDecoder（100个Object Queries）
    └── DETRHead → (B, 100, 6)

训练链路：
  detr_pred (B, 100, 6)
  → Hungarian 匹配选最佳 → best_query (B, 6)
  → query_proj(6→128)
  → fusion(dim_2d=128, dim_1d=64) → (B, 192)
  → output_head(192→6) → final_output (B, 6)
  loss = HungarianLoss + 0.5×SuperviseLoss

推理模式：argmax(conf) → query_proj → fusion → output_head → (B, 6)
```

## 五、训练/推理模式设计

**核心原则**：所有新变体（swin_yolo/vit_yolo/detr）统一使用 `self.training` 属性区分模式：

```python
if self.training:
    return raw_pred, global_density  # 用于损失计算
else:
    # 取最佳预测 → 融合 → 输出头
    output = self.output_head(self.fusion(best_pred, feat_1d))
    return output, global_density
```

**关键点**：
- 训练模式：返回原始预测（供损失函数使用）
- 推理模式：经过融合+输出头（用于实际预测）

## 七、训练时间估算

### 7.1 动态估算

训练开始前会自动测量2-3个epoch的实际速度：
- 保存/恢复模型状态，不影响训练
- 显示 "预估总时间: ~X小时"

### 7.2 实时 ETA

每10轮显示训练进度盒子：
```
║ System| EMA: 1.3s/epoch | ETA: 2m55s | 完成: 14:32 ±0.2s   ║
```

- **EMA**：指数移动平均，更稳定
- **置信区间**：至少5个epoch后显示
- **预计完成时间**：具体时间点

### 7.3 ETAEstimator 类

```python
from run_train import ETAEstimator

# 初始化
eta = ETAEstimator(total_epochs=150, alpha=0.3)

# 每轮更新
eta.update(epoch_time)

# 获取 ETA 信息
info = eta.get_eta(current_epoch)
# info: {'ema', 'eta_str', 'finish_time', 'confidence', ...}
```

### 9.3 检查点完成状态机制

**双保险检查点**：
- `{...}_best.pt`：仅在验证损失改善时更新
- `{...}_last.pt`：每个 epoch 结束无条件保存（崩溃兜底）

**分层目录**：
```
checkpoints/
├── resnet18/              # 按变体分子目录
│   └── detection_off0_best.pt
│   └── detection_off0_last.pt
├── swin_yolo/
│   └── ...
└── backup/                # 配置变更时自动备份
    └── ...config_changed_时间戳.pt
```

**文件命名**：`{task}_off{offset}_{best|last}.pt`（variant 在目录名而非文件名）
- 示例：`detection_off0_best.pt`（路径：`checkpoints/resnet18/detection_off0_best.pt`）
- 同一变体下不同 predict_offset 共存：`detection_off0_best.pt`、`detection_off1_best.pt`

**元数据字段**（torch.load 后可访问）：
| 字段 | 说明 |
|------|------|
| `is_complete` | `True`=训练正常结束，`False`=意外中断 |
| `is_retrain_done` | 强制重训完成后标记 |
| `epoch` | 已完成的 epoch 数（1-indexed） |
| `save_reason` | `improvement`/`epoch_end`/`early_stop`/`completed` |
| `task_id` | 团队协作任务 ID |
| `timestamp` | 保存时的 ISO 时间戳 |
| `config` | 完整训练配置（用于签名校验） |
| `_latest_best_path` | best.pt 实际路径（用于 `_mark_checkpoint_complete`） |
| `_latest_last_path` | last.pt 实际路径（用于 `_mark_checkpoint_complete`） |

### 9.4 配置签名校验

加载检查点时会自动校验配置字段，不匹配时会强制重训并备份旧文件：

**普通变体（resnet18/swin_yolo/vit_yolo/swin_yolo_patchtst）**：12 个字段

| 签名字段 | 说明 |
|----------|------|
| `variant`, `fusion`, `backbone_2d`, `backbone_1d` | 模型架构 |
| `task`, `predict_offset` | 任务模式 |
| `triple_channel`, `use_coord_attn`, `staged_train` | 训练策略 |

**DETR 专用**：12 + `image_size`（共 13 个字段）

DETR 的位置编码维度依赖 `image_size`（feat_size = image_size // 32），因此签名中必须包含 `image_size`。

> `fp16`、`epochs`、`patience`、`lr`、`batch_size` 等运行时参数**不在签名中**，变更不会触发重训（显存自适应参数变化不影响模型权重）。

### 9.5 Epoch 目标数变更

系统支持在不同运行间改变目标 epoch 数：

| 场景 | 行为 |
|------|------|
| 150 epoch 早停在 85，下次想跑 200 | 自动从 85 继续 |
| 跑了 3 epoch 测试，下次想跑 100 | 自动从 3 继续 |
| 跑完了 150 epoch，下次想跑 200 | 自动从 150 继续 |
| 跑完了 150 epoch，只想跑 100 | 直接返回（已达目标） |

### 9.6 检查点加载行为

**决策矩阵**：

| 检查点状态 | 配置签名 | 目标 Epoch > 已训练? | 行为 |
|------------|----------|---------------------|------|
| ✅ `is_complete=True` | ✅ 一致 | ✅ 是 | 从 saved_epoch 继续训练 |
| ✅ `is_complete=True` | ✅ 一致 | ❌ 否 | 直接返回 |
| ✅ `is_complete=True` | ❌ 不一致 | 任意 | 备份旧文件 + 强制重训 |
| ❌ 未完成 | ✅ 一致 | 任意 | 从断点恢复 |
| ❌ 未完成 | ❌ 不一致 | 任意 | 备份旧文件 + 强制重训 |

> 重新训练请删除检查点文件或使用 `--force_retrain`。

**强制重训**（配置签名不匹配时自动触发）是**正常行为**，不是错误：
- 旧检查点自动备份到 `checkpoints/backup/`
- 新训练完成后 `is_complete=True` 写入
- 后续运行直接加载，不再触发重训

### 9.7 续训状态透传（start_epoch + best_loss）

`train_variant` 加载 checkpoint 后必须把 3 个关键状态透传给 `train_model`，否则会出现"识别到 e008_last.pt 但从 epoch 1 重数"这类诡异 bug。

**`train_variant` 端**（run_train.py:2232 附近）：

```python

is_complete = checkpoint.get('is_complete', False)
best_loss = checkpoint.get('best_loss', float('inf'))

# 透传给 train_model
model, metrics = train_model(
    model, train_loader, test_loader, config, device, save_path, task_id=task_id,
    start_epoch=saved_epoch,   # 0-indexed：已训练 epoch 数
```

**`_find_latest_epoch_file` 解析**：

支持两种命名格式（向后兼容）：
- 新：`{base}_e{N:03d}_{best|last}.pt`（如 `detection_off0_e008_last.pt`）
- 旧：`{base}_{best|last}.pt`（如 `detection_off0_last.pt`）

**典型续训日志**（A4_long 实际跑出来的）：

```
[OK] 检测到意外中断的检查点: ./checkpoints/detr/baseline/detection_off0_e008_last.pt (Epoch 8)
[RESUME] 从 Epoch 9/150 继续训练（已训练 8 轮）
Epoch 9/150 | Loss: 0.3859 (Best: 0.3806) | LR: 9.70e-05 | Time: 495.4s
```

**常见错误**（修复前实际踩过的）：

| 现象 | 原因 | 修复 |
|------|------|------|
| 续训显示 `Epoch 1/150` | `train_model` for 循环硬编码 `range(config['epochs'])` | 改 `range(start_epoch, config['epochs'])` |
| 续训不保存 `e{N+1}_last.pt` | `last_checkpoint_path` 推断只处理 `_best.pt` 结尾 | 支持 `_last.pt` 结尾 |
| 续训第一个 epoch 瞎刷 best | `best_loss = float('inf')` 硬编码 | 透传 `best_loss=best_loss` |

### 9.8 训练历史 CSV

`logs/training_history/{task_id}.csv` 每个 epoch 追加一行，断点续训不重写。

**字段**：

| 字段 | 说明 |
|------|------|
| `timestamp` | ISO 时间戳 |
| `task_id` | 任务 ID |
| `variant` | 模型变体 |
| `subdir` | 子目录（baseline / gated / staged / ...） |
| `predict_offset` | 时间偏移 |
| `epoch` | 1-indexed |
| `train_loss` | 训练 loss |
| `val_loss` | 验证 loss |
| `best_loss` | 历史最优 loss |
| `lr` | 当前学习率 |
| `epoch_time_s` | 本轮耗时（秒） |

**特性**：
- append 模式：断点续训只追加新行
- 表头自动检测（`csv_needs_header = not os.path.exists(csv_path) or os.path.getsize(csv_path) == 0`）
- 通过 `atexit` 注册关闭钩子保证文件 flush
- 单文件单任务，不引入 DB

**示例**（A4_long）：

```csv
timestamp,task_id,variant,subdir,predict_offset,epoch,train_loss,val_loss,best_loss,lr,epoch_time_s
2026-08-11T13:24:17,A4_long,detr,baseline,0,7,0.389139,0.380532,0.380623,9.947e-05,530.54
2026-08-11T13:33:17,A4_long,detr,baseline,0,8,0.388649,0.380533,0.380623,9.931e-05,551.02
2026-08-11T16:27:14,A4_long,detr,baseline,0,9,0.385854,0.380610,0.380623,9.701e-05,491.62
```

### 9.9 检查点命名与目录卫生

**新格式**：`{base}_e{N:03d}_{best|last}.pt`

**配套**：
- `_delete_other_epoch_ckpts(subdir, kind, keep_epoch)` — 同目录下其他 epoch 的同名文件，保证最多 1 个 best + 1 个 last
- `_find_latest_epoch_file(base_path, ctype)` — 找最高 epoch，支持新旧格式

**目录约定**：
```
checkpoints/
├── resnet18/
│   ├── baseline/    # A1 + B1/B2/B3/B4/B5（实验分组，不是架构）
│   ├── gated/       # B1 变种
│   └── coord/       # B2 变种
├── swin_yolo/
├── detr/
│   └── baseline/    # A4 + A4_long（共享子目录，task_id 区分）
├── vit_yolo/
├── swin_yolo_patchtst/
└── backup/          # 配置变更 / 错命名 / dev scripts 归档
    ├── _save_reason_fix_YYYYMMDD/
    ├── _ckpt_cleanup_YYYYMMDD/
    ├── _dev_scripts_YYYYMMDD/
    ├── _buggy_ckpt_names_YYYYMMDD/
    └── _a4long_resume_test_YYYYMMDD/
```

> **subdir 是实验分组不是架构**：变体（resnet18/swin_yolo/vit_yolo/detr/swin_yolo_patchtst）是一级目录；subdir（baseline/gated/coord/...）是实验分组（同变体下不同实验配置共存），不是严格的架构分类。

## 十二、常见问题排查

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| CUDA: False | PyTorch 未安装 CUDA 版本 | `pip install torch --index-url https://download.pytorch.org/whl/cu118` |
| Loss 是 NaN | 学习率过高 | `--lr 1e-4` |
| 显存不足 | 批次过大 | `--image_size 256 --batch_size 4` |
| R² 为 0 | 图像尺寸不匹配 | 检查 `--image_size` 与训练一致 |
| 未找到数据 | 数据路径错误 | 检查 `config.json` 的 `data_root` |
| ViT 输入尺寸错误 | ViT 只接受 224 | 使用 `input_resize` 层 |
| DETR 特征图尺寸错误 | ResNet 未启用空间输出 | 调用 `set_spatial_output(True)` |
| DETR 位置编码维度错误 | feat_size=16 应为 8 | 已修复（stride=32 → dynamic feat_size） |
| staged_training YOLO 报错 | 模型参数缺失 | 已修复（补充完整参数） |
| GatedMultimodalFusion 精度低 | 输出只返回门控输出，丢失2D特征 | 已修复（改为 torch.cat 拼接） |
| PhysicalSafeTransform1D triple_channel 异常 | seq_len 取 len(seq) 对 (3,300) 返回3 | 已修复（改为 seq.shape[-1]） |
| CoordAtt 注入后报错 | BackboneWithAttention 未开启空间输出 | 已修复（注入前调用 set_spatial_output） |
| ViTYOLO / SwinYOLO-PatchTST 网格不匹配 | actual_grid_size 未动态计算 | 已修复（image_size//32 动态适配） |
| 续训时显示 `Epoch 1/150` 但加载了 e008_last.pt | `train_model` for 循环没接 `start_epoch` 参数 | 已修复（v4.6.10：新增 `start_epoch=0` 参数 + `range(start_epoch, config['epochs'])`） |
| 续训时不保存 `e{N+1}_last.pt` | `last_checkpoint_path` 推断只处理 `_best.pt` 结尾 | 已修复（v4.6.10：支持 `_last.pt` 结尾直接用作 last 路径） |
| 续训第一个 epoch 瞎刷 best（val_loss 差也保存） | `best_loss = float('inf')` 硬编码，不继承历史 | 已修复（v4.6.10：新增 `best_loss=None` 参数 + 透传 `best_loss=best_metric`） |
| CSV `UnboundLocalError: current_lr` | `current_lr` 在 NaN/Inf 防护 `continue` 路径未执行赋值 | 已修复（v4.6.8：把 `current_lr` 赋值移到 CSV 写入之前） |
| 团队训练显示 `is_complete=False` 永远未完成 | `_mark_checkpoint_complete` 早停 vs 正常结束混在一起 | 已修复（v4.6.8：显式 `terminated_by_early_stop` 参数） |
| team_train 进度表错判未完成 | `_print_progress_table` 用 `is_complete and last_epoch >= target`，`last.pt` 的 `last_epoch` 通常远小于 `target` | 已修复（v4.6.7：改为只判断 `is_complete`） |

## 十三、代码规范

### 13.1 命名规范

- 类名：`PascalCase`（如 `SwinYOLOFPN`）
- 函数名：`snake_case`（如 `estimate_training_time`）
- 常量：`UPPER_SNAKE_CASE`（如 `BOX_WIDTH`）

### 13.2 训练/推理模式

- **必须**使用 `self.training` 属性判断模式
- 训练模式返回原始预测供损失计算
- 推理模式返回最优预测

### 13.3 工具脚本存放规范

**新工具脚本必须放 `tools/`**，禁止在项目根目录写 `_sim_*.py` / `_verify_*.py` / `_check_*.py` / `_inspect.py` 等一次性调试脚本。

**命名约定**：`tools/{verb}_{noun}.py`
- `cleanup_old_ckpts.py` — 清理历史检查点
- `fix_save_reason.py` — 批量修复 `save_reason` 字段
- 不允许用 `_` 开头（暗示临时/一次性）

**临时调试脚本**：归档到 `checkpoints/backup/_dev_scripts_YYYYMMDD/`，命名 `_<purpose>.py`。
- 优点：跟正式工具区分；不污染项目根；保留下来给未来参考
- 缺点：不在 PATH；引用时用绝对路径

**示例**：

```powershell
# ✅ 正式工具
D:\team_project\projects\pe_mmnet\project_v4\tools\cleanup_old_ckpts.py

# ✅ 临时调试脚本
D:\team_project\projects\pe_mmnet\project_v4\checkpoints\backup\_dev_scripts_20260810\_verify_fix.py

# ❌ 项目根目录散落（已清理）
D:\team_project\projects\pe_mmnet\project_v4\_sim_bug.py
```
