## 三、模型变体详解

### 3.1 基础模型：PETSNetMultimodal（`resnet18`）

```
输入
├── 1D分支：(B, 300) 温度序列
│   ├── Micro1DCNN → 局部特征 (32维)
│   ├── Macro1DCNN → 全局趋势 (32维)
│   ├── Multi-Head Self-Attention → 通道融合
│   └── 输出：64维向量
│
└── 2D分支：(B, 2, H, W) 温度场+应力场
    ├── ResNet-18（ImageNet预训练）
    │   └── 输出：(B, 512, H', W')
    └── GlobalAvgPool → (B, 512) 向量

融合：CrossAttentionFusion(dim_2d=512, dim_1d=64)
输出：MultiTaskHead(576→6) → (B, 6) [x, y, l, w, conf, density]
```

**显存占用**：~2GB（batch=4，FP16）

---

### 3.2 SwinYOLOFPN（`swin_yolo`）

```
输入
├── 1D分支：TemporalFeatureExtractor → 64维
│
└── 2D分支：(B, 2, 512, 512)
    ├── SwinBackbone2D（timm Swin-Tiny，img_size=512）
    │   └── 输出多尺度特征，取最后一层 (B, 768, 16, 16)
    ├── yolo_proj：Conv2d(768→256) + BN + ReLU
    └── YOLOFPNHead → (B, 256, 6)

融合：CrossAttentionFusion(dim_2d=6, dim_1d=64)
输出：MultiTaskHead(70→6) → (B, 6)

训练模式：返回 (B, G², 6) 完整网格预测（G² = 16² = 256）
推理模式：取最高conf网格 → fusion → output_head → (B, 6)
```

**actual_grid_size**：固定为 16（硬编码），即固定 256 个网格预测。

**显存占用**：~4GB（batch=4，FP16）

---

### 3.3 ViTYOLOFPN（`vit_yolo`）

```
输入
├── 1D分支：TemporalFeatureExtractor → 64维
│
└── 2D分支：(B, 2, 任意尺寸) 图像
    ├── input_resize：Conv2d(2→3, kernel_size=1) + BN + ReLU（转换为3通道）
    ├── ViTYOLOBackbone2D（timm vit_small_patch16_224）
    │   └── 输出：(B, 256, 7, 7)（注意：骨干输出已为256通道，无384→256投影）
    ├── interp：Resize到 (16, 16)
    ├── fpn：Conv2d(256→256, kernel_size=3) + BN + ReLU
    └── YOLOFPNHead → (B, 256, 6)

融合：CrossAttentionFusion(dim_2d=6, dim_1d=64)
输出：MultiTaskHead(70→6) → (B, 6)

训练模式：返回 (B, 256, 6) 固定256网格
推理模式：取最高conf → fusion → output_head → (B, 6)
```

**grid_size 动态计算**：内部通过 `image_size // 32` 并取最近的 4 的倍数，确保适配 YOLO head。

**显存占用**：~3GB（batch=4，FP16）

---

### 3.4 SwinYOLOFPNWithPatchTST（`swin_yolo_patchtst`）

```
输入
├── 1D分支：(B, 300) PatchTST1D
│   ├── PatchEmbedding：patch_len=10 → 30 patches, d_model=64
│   ├── 可学习位置编码
│   ├── Transformer Encoder（2层，4头）
│   └── 输出：64维向量（与 TemporalFeatureExtractor 维度一致）
│
└── 2D分支：(B, 2, 512, 512)
    ├── SwinBackbone2D（timm Swin-Tiny）
    │   └── 输出多尺度特征，取最后一层 (B, 768, G, G)
    ├── yolo_proj：Conv2d(768→256)
    └── YOLOFPNHead → (B, G², 6)

融合：CrossAttentionFusion(dim_2d=6, dim_1d=64)
输出：MultiTaskHead(70→6) → (B, 6)

训练模式：返回 (B, G², 6) 完整网格预测（G² = actual_grid_size²）
推理模式：取最高conf → fusion → output_head → (B, 6)
```

**actual_grid_size**：通过 `max(16, (image_size//32 // 4) * 4)` 动态计算，确保适配 YOLO head。

**优势**：
- PatchTST 比 TemporalFeatureExtractor 更适合长序列时序建模
- Patch 机制捕获局部时序模式
- Transformer 全局注意力捕获长程依赖
- 有 fallback 机制（导入失败时使用 TemporalFeatureExtractor）

**显存占用**：~4GB（batch=4，FP16）

---

### 3.5 DETRStyle（`detr`）

```
输入
├── 1D分支：TemporalFeatureExtractor → 64维
│
└── 2D分支：(B, 2, 256, 256)
    ├── ResNet18Backbone2D（启用 set_spatial_output=True）
    │   └── 输出：(B, 512, 8, 8)（固定，与 image_size 无关）
    ├── input_proj：Conv2d(512→512)
    ├── PositionalEncoding2D：动态匹配特征图尺寸
    ├── flatten + transpose → (B, 64, 512)
    ├── TransformerEncoder（6层）
    ├── DETRDecoder（100个Object Queries）
    └── DETRHead → (B, 100, 6)

训练链路：
  detr_pred (B, 100, 6)
  → Hungarian 匹配选最佳 query → best_query (B, 6)
  → query_proj(6→128)
  → fusion(dim_2d=128, dim_1d=64) → (B, 192)
  → output_head(192→6) → final_output (B, 6)
  loss = HungarianLoss(detr_pred) + 0.5×SuperviseLoss(final_output)

推理模式：
  detr_pred → argmax(conf) → best_query → query_proj → fusion → output_head → (B, 6)
```

**显存占用**：~5GB（batch=4，FP16）

## 四、损失函数选择

| 变体 | 损失函数 | 目标分配 |
|------|----------|----------|
| `resnet18` | `MultimodalCrackLoss` | 直接比较（6维向量L1/L2） |
| `swin_yolo` | `YOLOLoss` + `YOLOTargetAssigner` | 网格分配，固定 16×16=256 |
| `vit_yolo` | `YOLOLoss` + `YOLOTargetAssigner` | 网格分配，dynamic（至少16） |
| `swin_yolo_patchtst` | `YOLOLoss` + `YOLOTargetAssigner` | 网格分配，dynamic（至少16） |
| `detr` | `DETRLoss` + `HungarianMatcher` | 最优匹配（100个Object Queries） |
| `segmentation` | `SegmentationLoss` | Dice + BCE |
| `multitask` | `MultimodalSegmentationLoss` | 检测+分割联合 |
| 密度优化 | `CombinedDensityLoss` / `DensityConsistencyLoss` | 邻域一致性约束（可选） |

## 五、训练/推理模式设计

所有新变体（swin_yolo/vit_yolo/detr/swin_yolo_patchtst）统一使用 `self.training` 属性区分模式：

```python
if self.training:
    return raw_pred, global_density  # 用于损失计算
else:
    # 取最佳预测 → 融合 → 输出头
    output = self.output_head(self.fusion(best_pred, feat_1d))
    return output, global_density
```

**关键原则**：
- 训练模式：返回原始预测（供损失函数使用）
- 推理模式：经过融合+输出头（用于实际预测）

## 八、检查点系统

### 8.1 文件命名

**新格式（v4.6.6+）**：`{base}_e{epoch:03d}_{best|last}.pt`

- `base = {task}_off{offset}`（不含变体，变体在目录名）
- epoch 用 3 位零填充：`e001`, `e008`, `e150`
- best 和 last 的 epoch 可能不同：val_loss 没改善时 best 保留之前的

**示例**：

```
checkpoints/detr/baseline/
├── detection_off0_e008_last.pt   # 第 8 轮保存的 last
├── detection_off0_e009_best.pt   # 第 9 轮 val_loss 改善，刷新 best
└── detection_off0_e009_last.pt   # 第 9 轮兜底
```

**配套函数**：

- `_find_latest_epoch_file(base_path, ctype)` — glob `{base}_e*_{ctype}.pt`，按 epoch 数字取最大
- `_delete_other_epoch_ckpts(subdir, kind, keep_epoch)` — 删除同目录下除 `keep_epoch` 外其他 epoch 的同名文件
- 保证每个任务目录里**最多 1 个 best + 1 个 last**

**旧格式**：`{variant}_{task}_off{offset}_{best|last}.pt`（无 epoch 后缀）

- 仍然兼容（`_find_latest_epoch_file` 会回退）
- 新训练一律用新格式

### 8.2 双保险机制

| 文件 | 保存时机 | 用途 |
|------|----------|------|
| `e{N:03d}_best.pt` | val_loss 改善时（`< best_loss - min_delta`） | 评估 / 部署 |
| `e{N:03d}_last.pt` | 每个 epoch 结束无条件 | 断点续训（**v4.6.6+ 续训来源从 best.pt 改为 last.pt**） |

**为什么 best 和 last 分开**：
- best 用于评估（取历史最优）
- last 用于续训（取最新状态）
- 续训来源从 `best.pt` 改为 `last.pt`，更符合"断点恢复"语义

### 8.3 续训流程

```
启动训练
   ↓
train_variant: 查找 base_path = {ckpt_subdir}/{task}_off{offset}
   ↓
_find_latest_epoch_file(base_path, 'last') → save_path (latest .pt)
   ↓
加载 checkpoint:
   is_complete = ckpt.get('is_complete', False)
   saved_epoch = ckpt.get('epoch', 0)  # 1-indexed
   best_loss = ckpt.get('best_loss', float('inf'))
   ↓
决策矩阵:
   is_complete=False → 从断点恢复 (start_epoch=saved_epoch)
   is_complete=True, target>saved → 继续训练 (start_epoch=saved_epoch)
   is_complete=True, target<=saved → 直接返回
   签名不匹配 → 备份旧 ckpt + 强制重训
   ↓
train_model(model, ..., start_epoch, best_loss)
   ├─ best_loss = best_loss  # 继承历史最优
   ├─ for epoch in range(start_epoch, config['epochs']):
   │   ├─ val_loss 改善 → 保存 e{epoch+1:03d}_best.pt
   │   └─ 每轮结束 → 保存 e{epoch+1:03d}_last.pt
   ├─ _delete_other_epoch_ckpts(subdir, 'best', epoch+1)
   └─ _delete_other_epoch_ckpts(subdir, 'last', epoch+1)
   ↓
_mark_checkpoint_complete() → 写回 is_complete=True
```

**3 个关键状态必须透传**（v4.6.10 修复）：

| 状态 | 来源 | 不透传会怎样 |
|------|------|--------------|
| `start_epoch` | `ckpt.get('epoch', 0)` | 续训从 epoch 1 重数，保存 `e001_best.pt` 覆盖历史 |
| `best_loss` | `ckpt.get('best_loss', inf)` | 第一个 epoch 必然刷 best，污染历史最优 |
| `last_checkpoint_path` | 从 `checkpoint_path` 后缀推断 | 续训不保存 `_last.pt` |

### 8.5 配置签名校验

加载 checkpoint 时对 `config` 字典的 14 个关键字段做严格比对，**任意一个不匹配**就触发强制重训 + 备份旧文件：

**普通变体（13 个字段）**：

| 字段 | 说明 |
|------|------|
| `task`, `predict_offset` | 任务模式 / 时间偏移 |
| `variant`, `fusion` | 模型架构 / 融合策略 |
| `backbone_2d`, `backbone_1d` | 骨干选择 |
| `triple_channel`, `use_coord_attn`, `staged_train` | 训练策略 |
| `feature_len`, `seq_interp_mode` | 数据处理 |

**DETR 额外**：`image_size`（位置编码维度依赖 `image_size // 32`）

> **不在签名里**：`fp16`/`epochs`/`patience`/`lr`/`batch_size` —— 运行时参数变更不影响模型权重兼容性。
