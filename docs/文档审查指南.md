## 三、通用审查维度

### 3.1 准确性审查（最重要）

**核心原则**：文档必须与实际代码一致。

#### 必查项

| 检查项 | 审查方法 |
|--------|----------|
| CLI 参数是否存在 | `grep -n "add_argument" run_train.py` |
| 函数签名是否正确 | `python -c "import inspect; from run_train import train_model; print(inspect.signature(train_model))"` |
| 默认参数值是否正确 | 检查源代码中的默认值 |
| 函数/类名是否正确 | 对照 `models/`, `training/` 源文件 |
| 损失权重默认值是否正确 | 检查 `training/mono_loss.py` 中的默认值 |
| 硬件要求/显存占用是否合理 | 对照代码中的显存检测逻辑 |

#### 常见错误模式

- ❌ 文档写了 `--use_se` 但实际只有 `--use_coord_attn`
- ❌ 文档写了 `patience=20` 但实际默认 `patience=30`
- ❌ 文档写了 `lr=3e-4` 但实际默认 `lr=1e-4`（架构自适应调整为 `1e-3`）
- ❌ 描述了不存在的函数/类
- ❌ `train_model` 签名缺 `start_epoch` / `best_loss`（v4.6.10+ 已有）

#### 验证命令

```bash
# 验证参数存在
grep -n "use_se\|use_coord" run_train.py

# 验证函数签名
/c/Users/LZXdywtgtd/.conda/envs/pe_mmnet/python.exe -c "
import inspect
from run_train import train_model
print(inspect.signature(train_model))
"

# 验证模型架构
/c/Users/LZXdywtgtd/.conda/envs/pe_mmnet/python.exe -c "
from models.pe_tsnet_yolo import ViTYOLOFPN
import torch
m = ViTYOLOFPN()
print([(n, type(p).__name__) for n, p in m.named_children()])
"
```

### 3.3 一致性审查

#### 跨文档一致性

同一信息在多个文档中出现时，必须保持一致：

| 必查一致性项 | 涉及文档 |
|------------|----------|
| 默认 patience 值 | 快速配置指南、调参指南、算法报告、开发人员文档 |
| 默认学习率 | 用户指南、调参文档、开发人员文档 |
| 模型显存占用 | 架构设计文档、用户指南、团队协作指南 |
| 模型输入尺寸 | 架构设计文档、用户指南 |
| 任务 ID 命名 | 团队协作指南、开发人员文档、CHANGELOG |
| 损失函数默认值 | 架构设计文档、调参文档 |
| 签名字段数 | 架构设计文档（13 个）、开发人员文档（12 + DETR 额外 1） |

#### 跨文档一致性脚本

```python
import os, re
keywords = ['1e-4', 'patience', 'checkpoints/', 'is_complete', '_e\\d{3}']
for root, _, files in os.walk('docs'):
    for f in files:
        if f.endswith('.md'):
            path = os.path.join(root, f)
            with open(path, 'r', encoding='utf-8') as fp:
                content = fp.read()
            for kw in keywords:
                if re.search(kw, content):
                    # 报告每处出现
                    for ln, line in enumerate(content.splitlines(), 1):
                        if re.search(kw, line):
                            print(f'{path}:{ln}: {line.strip()[:120]}')
```

## 五、审查流程

### Step 1：代码审查

修改代码后，先确认需要更新的文档：

1. 新增/修改了 CLI 参数 → 更新用户指南、调参文档、开发人员文档
2. 新增/修改了模型架构 → 更新架构设计文档
3. 新增/修改了损失函数 → 更新架构设计文档、调参文档
4. 新增/修改了公开函数 → 更新 API 文档
5. 新增/修改了团队协作功能 → 更新团队协作指南

### Step 2：文档自检

按照本指南 §三 通用审查维度逐项检查。

### Step 3：交叉引用验证

```python
import os, re
for root, _, files in os.walk('docs'):
    for f in files:
        if f.endswith('.md'):
            path = os.path.join(root, f)
            with open(path, 'r', encoding='utf-8') as fp:
                content = fp.read()
            for link in re.findall(r'\]\(([^)]+\.md)\)', content):
                base = os.path.dirname(path)
                target = os.path.normpath(os.path.join(base, link))
                if not os.path.exists(target):
                    print(f'BROKEN: {path} -> {link}')
```

## 六、常见问题速查

| 文档问题 | 根因 | 解决方案 |
|----------|------|----------|
| 参数不存在 | 文档基于旧版代码 | 对照 `run_train.py` 重新确认 |
| 默认值不对 | 未同步最新默认值 | 从源代码读取实际默认值 |
| 链接断裂 | 文件重命名后未更新引用 | 用 grep 搜索旧文件名并替换 |
| 架构描述不一致 | 不同文档由不同人维护 | 以架构设计文档为准，其他文档引用 |
| 缺少新增内容 | 审查时未对照源代码 | 必须阅读源代码后再审查 |
| 引用 A4_long | A4_long 已合并到 A4 | 替换为 A4（v4.6.11+） |
| `train_model` 签名缺参数 | 文档基于 v4.6.10 之前 | 补上 `start_epoch` 和 `best_loss` |
| 显存配置表错误 | 文档基于 v4.6.6 之前 | 重写为 4 行（≥10/6-10/4-6/<4 GB） |
| 检查点命名格式旧 | 文档基于 v4.6.6 之前 | 重写为 `{base}_e{N:03d}_{best\|last}.pt` |
