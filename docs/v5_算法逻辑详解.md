# PE-MMNet v5-α 算法逻辑详解

> 定位：与 `v5_架构设计.md`（设计视角）互补——本文回答"**每一步实际怎么运作**"，
> 逐层讲物理仿真 → 数据打包 → 网络前向 → 损失监督的完整链路。
> 依据代码（v5.0.18 收官版，commit 5900955）：
> `data/patch_simulator_v5.py`、`data/_dprime_generator.py`、`data/patch_dataset_v5.py`、
> `models/pe_tsnet_detr_v5.py`、`models/spline_head.py`、`models/gp_module.py`、
> `training/ordered_kp_loss.py`、`training/trainer_v5.py`、`training/data_aug_v5.py`。
> 收官数字（197/197、chamfer p50=1.60px、ratio 0.426~0.441）见 CHANGELOG v5.0.18。

## 0. 任务定义

**输入**：陶瓷坯体烧制过程的一维温度时序（300 点）+ 烧制结束时刻的二维多通道场图
（128×128）。

**输出**：裂纹的位置——一个包围框（bbox，归一化 xyxy）+ 沿裂纹骨架的 8~16 个
有序关键点（归一化 y,x）。

**训练数据来源**：不是真实窑炉，而是物理仿真器——这是 v5-α"仿真路线"的全部含义；
v5-β 真实数据路线因外部条件（无烧后样品、无法窑内采集等）短期暂缓
（前置五问见 `v5b_立项依据.md`）。

整个系统分四层：**物理仿真产生数据 → 数据打包成模型输入 → 网络预测 → 组合 loss
监督**。

## 1. 物理仿真层：数据从哪来

### 1.1 热传导——温度场怎么演化

`PatchSimulator.simulate()`（patch_simulator_v5.py L146）。

128×128 像素网格代表坯体横截面，初始全场 20°C 室温 + 随机初温噪声（每个样本
不同）。按三段烧成曲线（升温→保温→降温，配置可换）做时间步进：

- **内部像素**：五点差分格式的热扩散方程 ∂T/∂t = α∇²T——每个像素新温度 =
  自己 + 扩散系数 ×（四邻居与自己的温度差）。物理含义：热从高温处向低温处
  摊平，摊平速度由热扩散率 α 决定。
- **边界像素**：Robin 边界（对流 + 辐射）——窑内环境以对流
  h·(T_target−T) 和 Stefan-Boltzmann 辐射 ε·σ(T⁴−T_env⁴) 两种方式给边界
  加热。**这个边界条件是本项目最大坑的来源**（见 1.3/1.4）。

### 1.2 应力场——Maxwell 粘弹性模型

`MaxwellStress`（data/viscoelastic.py）。每个时间步，温度变化 ΔT 产生热应力，
用 Maxwell 松弛模型的显式 Euler 离散：

```
σ(t+1) = σ(t) + E·α_T·ΔT/(1−ν) − (dt/τ)·σ(t)
```

- **第一项（产生）**：温度变化 × 热膨胀系数 × 弹性模量，除以 (1−ν) 是平面
  应力修正。温度骤变处产生应力。
- **第二项（松弛）**：应力随时间指数衰减，τ 是松弛时间。物理含义：陶瓷高温下
  像 极粘的液体一样"松弛"掉应力——慢升温不裂的原因（D' 实验的关键）。

同时维护**全程峰值拉应力场** σ_max：每步 elementwise max。裂纹判定用峰值而
非瞬时值——裂纹在升温/保温阶段萌生，之后应力松弛掉了裂纹也已存在。

### 1.3 GT 提取——从应力场到裂纹真值

`_extract_crack_mask()` + `_extract_keypoints()`（patch_simulator_v5.py
L342/L455）。裂纹 GT 不是真实裂纹，而是**"峰值拉应力超过阈值 th（60 MPa）
的位置"经形态学清理后的结果**：

1. **阈值化**：σ_max > 60 MPa 的像素 = 候选裂纹
2. **边界框剥离**（V5-032）：≥2 条外边线覆盖 ≥90% → Robin 边界加热造成的
   系统性应力框（几何伪影），剥四边各 2px
3. **保留最大连通域**：只留最大一块
4. **闭运算**（border_value=1，V5-024 修）：连接断裂处；border_value=1 是为
   不腐蚀贴边细线
5. **二次保留最大连通域**（V5-028 修）：闭运算的膨胀在四角产生 ≤4px 假
   分量，再清一次

从 mask 提取监督目标：

- **关键点**：mask 骨架化 → 找端点 → 取**最远端点对**（V5-034 修：不能盲取
  前两个端点，idx=101 曾因此选中短枝对，114 点主干被压成 2×7px）→ 沿骨架
  BFS 追路径 → **等弧长采样 K 个点**（K 随机 ∈ [8,16]）
- **bbox**：mask 包络，归一化 xyxy

### 1.4 D' 数据变体——让 GT 变得可学

`DPrimePatchSimulator`（data/_dprime_generator.py）。

默认配置的致命问题：**均匀边界加热下，应力集中在边界框，内部几乎没有线状
裂纹**。V5-025 诊断确认根因是**热扩散是空间低通滤波**：慢烧曲线（11.7 小时）
扩散长度 52px，把任何局部调制抹平（对比度 9.21× → 1.12×）。

方案 D'：**子类化仿真器，只重写边界条件**——四条边各自乘空间调制的对流系数
h（每条边随机选 1/3~2/3 长度的段，强度 ×2/×3/×4 随机；辐射项不动）。调制段
下方局部加热快 → 与未调制区产生温差 → **线状内部高应力区** → 阈值化后就是
线状裂纹 GT。同时**必须用快烧曲线**（11 分钟，扩散长度 7px ≪ 段宽，调制才能
存活到结束）。

收官数据口径即 `fast+D'+th60`。物理对应"窑炉某侧加热元件功率不均导致局部
过热开裂"场景。

## 2. 数据层：模型看到什么

`PatchDatasetV5`（data/patch_dataset_v5.py）。每个样本打包成两个输入 +
四个监督目标：

**x_1d（一维时序）**：温度场历史最后 300 帧的**全图空间平均**，归一化
[0,1]。编码"这条烧成曲线长什么样、现在烧到哪个阶段"。

**x_2d（三维图像）**，三通道分别为：

1. 最终温度场（归一化）——哪里热哪里冷
2. 最终应力场（归一化）——哪里应力集中（瞬时应力，松弛后大部分区域接近零，
   调制段边缘仍有残余）
3. 热力图（最终温度场的另一种渲染）

**监督目标**：bbox（4 维）、关键点（变长 K∈[8,16]，−1 pad + mask）、裂纹
像素坐标（变长 N，−1 pad + mask，供 chamfer 用）。

全部样本预生成后落 npz 缓存（1000 train + 200 val）。**缓存键包含
patch_size / seed / 热曲线哈希 / 阈值 / 数据变体标记 dp|sd+gs**（V5-033 P0
根治：键缺数据语义曾导致 augfix1 用 stock 数据训了 150ep；现在 dprime 键
miss 时直接报错拒绝，不允许用 stock 现场仿真冒充）。

## 3. 网络层：预测怎么产生

`DETRStyleV5`（models/pe_tsnet_detr_v5.py）。

```
x_2d ─→ ResNet-18 ─→ 1×1投影到512维 ─→ 加2D位置编码 ─→ Transformer encoder(6层)
                                                              ↓ memory (H'×W', 512)
                                              DETR decoder(100个query, 6层)
                                                              ↓
                                    DETRHead: 每个query出6维(x1,y1,x2,y2,conf,class)
                                                              ↓
                                    取conf最高的1个query ── 6维 → 线性投影到128维
                                                              ↓
x_1d ─→ TemporalFeatureExtractor(小型Transformer) ──── 64维  拼接 → 192维融合特征
                                                              ↓
                                                     GPModule 调制
                                                              ↓
                                                     SplineHead 输出
```

逐段：

- **ResNet-18 骨干**：把 3×128×128 场图压成 512×4×4 特征图（stride 32）。
  负责"看"——从温度/应力分布提取空间模式。ImageNet 预训练权重可用
  （3 通道恰好兼容）。
- **Transformer encoder**：对 16 个空间位置（4×4）做全局自注意力，让每个
  位置"知道"其他位置——裂纹位置不只取决于本地应力，还取决于与远处的温差
  对比。
- **DETR decoder**：100 个可学习 query 向量去 memory 里"查"信息。每个
  query 最终给出候选框+置信度。**关键设计：训练和推理都只取置信度最高的那
  一个 query**（裂纹是单实例任务，不需要 DETR 原版的集合匹配）。这个 6 维
  向量浓缩了"网络认为裂纹在哪"。
- **1D 分支**：300 点温度时序过 4 头小型 Transformer，输出 64 维，提供
  "烧成工艺上下文"。
- **融合**：DETR query（投影 128 维）拼接 1D 特征（64 维）= 192 维。物理
  含义：裂纹位置（2D 空间证据）+ 工艺阶段（1D 时间证据）合并。

### 3.1 GPModule——batch 内样本平滑先验

models/gp_module.py。实际运作方式：把 **batch 内的 B 个样本**当高斯过程的
B 个采样点，RBF 核 K_ij = σ²·exp(−‖x_i−x_j‖²/2ℓ²) 算样本间相似度，然后做
**GP 平滑**：每个样本的新特征 = 所有样本特征的核加权平均。直觉：特征相近的
样本应有相近的调制——引入**样本间平滑性先验**（不是像素平滑，是 batch 内
样本平滑）。

核超参 ℓ（长度尺度）、σ² 可学习，另有一项正则把 ℓ 拉回 1 附近（防"无
平滑"ℓ→0 或"全糊"ℓ→∞）。技术细节：高维特征的距离平方期望是 in_dim 量级，
会直接把核打到单位矩阵，故先做 L2 归一化（除 sqrt(in_dim)）让距离变 O(1)。
batch=1 时退化为纯残差路径（无 GP 意义）。

### 3.2 SplineHead——输出头

models/spline_head.py。192 维融合特征过两层 MLP（256→128），分四个头：

- **bbox 头**：4 维 sigmoid 到 [0,1]，再 min/max 重参数化保证 x1≤x2、
  y1≤y2（网络输出任意四个数，"角点顺序错了"这个问题从损失函数移到结构里，
  永远合法）
- **关键点头**：固定输出 **16×2**（max_kpts），sigmoid 到 [0,1]，(y,x)
- **validity 头**：16 维，每点"是不是真点"的概率
- **K 头**：1 维 sigmoid 映射到 [8,16] 整数

**重要的结构-监督不匹配**：模型固定吐 16 个点，GT 是 8~16 变长。v5-α 收官
配置下 validity 和有序监督默认关闭（λ=0），16 个点全部由 chamfer/kpt_direct
无序监督。推理接口 `predict_kpts_only` 才做"按 validity 截断到 K、按 x 排
序"——但收官评估走的是"样条→像素 chamfer"判据，不依赖 validity（V5-030
候选 1 方案 B 未转正的直接后果：validity 从未被有效监督，150ep 后
std 0.247 ≈ 随机）。

## 4. 损失层：拿什么监督

`OrderedKeypointLoss`（training/ordered_kp_loss.py）。总损失 = 七项加权
（收官权重）：

```
total = 1.0  × coverage      双向 chamfer（经样条）
      + 0.5  × kpt_direct    关键点直连最近真像素
      + 1.0  × bbox          Smooth L1
      + 0.1  × gp            GP 核超参正则
      + 0.05 × poisson       关键点等弧长先验
      + 0    × ordered       有序监督（V5-030 实验，收官关闭）
      + 0    × validity      （同上）
```

### 4.1 coverage（核心项）的运作机制

1. 模型预测的 16 个点用 **Catmull-Rom 三次样条**连成光滑曲线（纯 PyTorch
   实现、可微——刻意选择：scipy 样条不可微，梯度传不回关键点；端点镜像
   延拓补 ghost points 保证切线连续）
2. 样条上密集采样 M=200 个点
3. **正向 chamfer**：每个真值裂纹像素到样条的最近距离，取均值——"样条要
   盖住所有真裂纹"
4. **反向 chamfer**：样条上每个采样点到最近真像素的距离，取均值——"样条
   不许跑到裂纹外面去"
5. 两者相加。**反向项是 v5a6 平台解事故后加的**：原来只有正向时，样条可以
   "摊大饼"罩住整个裂纹区域白拿低 loss（边界角点作弊解 0.0148 < 真关键点
   0.0925），加反向才堵死
6. **padding 掩蔽**：batch 里负样本（无裂纹）的真值像素是 −1 填充，不 mask
   的话 9 万个假像素污染监督——v5a6 平台解的另一个根因

### 4.2 其余各项

- **kpt_direct**：chamfer 的梯度要穿"关键点→样条→距离"两层，样条在饱和区
  梯度病态，早期模型关键点集体塌缩。kpt_direct 完全绕开样条：每个预测点
  直接拉向最近真像素（L2）。两监督互补——chamfer 管整体形状，direct 管
  单点落位。
- **poisson**：相邻关键点段长的方差。裂纹上采样点应大致均匀（GT 也是等弧长
  采的），防 16 个点挤成一团。
- **bbox**：Smooth L1，预测框四角对真值框四角。
- **GP 正则**：惩罚 (log ℓ)² + (log σ²)²，把核超参往 1 拉的弹簧。

### 4.3 评估判据（v5-α 收官）

- **判据 4（主指标）**：chamfer ratio = 预测样条 vs 真值像素的 chamfer /
  **GT 骨架自洽 chamfer** ≤ 1.5——分母是"GT 骨架自己拟合自己的 chamfer"，
  即完美预测的基准线。收官 197/197 全过（0.426~0.441）
- 判据 3：跨输入方差口径
- 判据 1/2：bbox 和关键点基础指标

## 5. 训练层

- **增广**（training/data_aug_v5.py）：hflip/vflip/rot90 各 50%，图像与全部
  GT（bbox/kpts/pixels）同步变换。**rot90 曾有 bug**：标签转了 rot180（增广
  后 GT 与图像错位 90°），V5-031 修复后判据 4 才首次 PASS——此前模型在
  "带噪声的错位标签"上训练，能到 93/94% 但上不去 100%。
- **种子分离**（V5-033）：`--seed` 管数据（仿真采样），`--train_seed` 管训练
  （初始化/dropout/shuffle）。5 个训练 seed 全 100% 的稳定性证据靠这个测出。
- **checkpoint 选择**：按 **val_coverage argmax** 选 best epoch（V5-030 后
  口径，不是 val_loss——loss 会过拟合，coverage 直接对齐任务指标）。

## 6. 全链路一图流

```
┌─ 仿真层 ─────────────────────────────────────────────┐
│ 快烧曲线(11min) × Robin边界(D'调制h) → FDM热扩散      │
│   → Maxwell应力松弛 → 峰值拉应力场                    │
│   → th=60阈值化 → 剥边界框/清伪分量 → 线状裂纹mask     │
│   → 骨架化+最远端点对+等弧长 → GT kpts(8~16) + bbox    │
└──────────────────────────────────────────────────────┘
                    ↓ npz缓存（键含数据变体标记）
┌─ 输入 ───────────────────────────────────────────────┐
│ x_1d = 温度历史最后300帧的全图均值（工艺曲线）          │
│ x_2d = [最终温度场 | 最终应力场 | 热力图] 3×128×128    │
└──────────────────────────────────────────────────────┘
                    ↓
┌─ 网络 ───────────────────────────────────────────────┐
│ ResNet18 → Transformer enc → DETR dec(100 query)     │
│   → top-1 query(6维) ──┐                             │
│ 1D时序 → Transformer ──┤ 拼接192维 → GP平滑 → MLP     │
│                        ↓                             │
│   SplineHead: bbox(4) + kpts(16×2) + validity + K    │
└──────────────────────────────────────────────────────┘
                    ↓
┌─ 监督 ───────────────────────────────────────────────┐
│ Catmull-Rom样条(可微) ← 16个预测点                    │
│ coverage = 正向chamfer(真像素→样条) + 反向(样条→真像素)│
│          + padding掩蔽                                │
│ kpt_direct(绕样条直连) + bbox SmoothL1 + GP正则       │
│          + poisson等弧长                              │
└──────────────────────────────────────────────────────┘
```

## 7. 三个设计本质

1. **GT 是物理的，但监督目标是"应力阈值"不是"裂纹"**——模型学的是"从
   温度/应力场反推峰值应力超阈值的位置"。这是仿真路线的全部 validity
   边界：真实陶瓷裂纹的萌生判据若不是拉应力阈值化，迁移到真实数据时 GT
   语义会变（v5-β 五问悬而未决的原因之一）。

2. **样条是模型和 loss 之间的"翻译官"**——模型输出离散点，GT 是像素集，
   可微样条让"点集→曲线→到像素集的距离"整条链梯度可传。所有重大事故
   （摊大饼解、塌缩、平台解）都发生在这个翻译环节的监督设计上，三次修复
   （双向 chamfer、padding 掩蔽、kpt_direct 直连）都是在补这条链的漏洞。

3. **架构上最非常规的选择是 DETR 只取 top-1 query**——检测范式用在单实例
   回归上，等于花 100 个 query 的成本换"网络内部先做候选竞争再输出"的
   结构。V5-030 曾拿 DETR 对照实验质疑过架构必要性，结论保留（判据 4 的
   结构上限与 query 数无关，粗簇失败是 4×4 位置瓶颈）。
