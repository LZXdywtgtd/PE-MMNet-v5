# 开篇前提：这份文件为什么放在总领文件夹（而非 pe_mmnet 目录下）

这份文件以 pe_mmnet 家族为案例，但放在总领文件夹（与 WORKFLOW.md 同级）是因为它承载的规则适用于知识库**全部注册项目**：

**任何项目结论都有三个坐标——出自哪个项目/哪个版本（或阶段）、在什么数据上、在什么条件下测得。脱离坐标引用结论，必然得出错误判断。**

pe_mmnet v2 是最典型的教训：孤立地看 v2（R²=0.9829、推理 0.85ms），会得出"模型早已达标"——但那是公式生成数据上的"假考题"，直到 v3 消融实验（仅时序分支 R²=0.0374）才戳破；反过来，只看 v4 的 R²=-0.26 而不知道 v2 的教训，又会误判"项目一直失败"。版本/阶段因果链两头都不能断。

这条规则同样约束知识库其他项目（仅举索引层事实）：
- **j_pinn_repro**：E_L2=30.1% 必须与"论文 0.91%"成对出现——单引 30.1% 会被读成失败，单说"已复现"会被读成达标；
- **ceramic-dl**：状态是"翻译完成、复现评估未启动"——引"翻译完成"暗示有复现成果即为虚报；
- **pinn_fracture_no_grad**：决策为"③ 局部借鉴"——引用其代码须注明"未完整复现，仅方法学片段"。

**硬规则（对全知识库生效）：引用任何项目的任何数字或状态之前，先读该项目的 PROJECT_INDEX.md 与演进/决策记录，定位三坐标；且必须能在对应项目目录复查到原始记录。**跨项目引用（如 A 项目的计划书引 B 项目的实验数字）是最高风险场景——2026-09 审计中，new_project2316/docs/4 瓷韵智造计划书引用 pe_mmnet v2 数字出错（0.968 为训练中间值/去约束变体值、12.4ms 全库无出处），即为本规则的反面例证。

## pe_mmnet v1→v5 演进史（全文规则的应用案例）

### v1（2026-04，已归档）
没有独立目录（在 `archive/pe_mmnet_v1_archive/`，已清理），只剩 `项目申请书_v1.docx`。**定位**：项目起点，可行性论证阶段。
**升级原因**：单任务雏形验证后需要正式的模型与实验体系。

### v2（2026-04~05）：温度时序 → 标量裂纹密度
**做了什么**：PE-TSNet 第一代（16 万参数，双分支 1D-CNN + 多头注意力），输入一条温度时序，输出**一个标量**（裂纹密度）。配套 `data_generator.py`——牛顿冷却公式生成温度序列、Griffith 近似公式直接算裂纹密度标签。首次引入**单调性损失**（mono_loss：裂纹密度必须随温度损伤单调增，禁止“裂纹自愈”的非物理预测）。
**实验结果**：R²=0.9829，推理 0.85ms，8 种子稳定（experiment_results 有完整记录，这是全家族唯一一次跑完 8 种子的对比实验）。
**暴露的问题（为什么升级）**：①数字漂亮但是**假考题**——温度序列和标签出自同一个公式族，模型只是在拟合出题公式；②团队自己提出核心质疑：**单维温度时序的信息量不足以反演裂纹的空间分布**（一条线推不出一张图）；③输出一个标量，工艺上无法使用——不知道裂纹在哪、什么形状。

### v3（2026-07）：引入多模态空间场
**做了什么**：v3 设计文档原文——“**摒弃单一标量预测，实现多模态数据输入**”。输入升级为 COMSOL 导出的 256×256 温度场+应力场图像，ResNet-18 双分支 + Cross-Attention 融合，输出升级为 **6 维向量 [x,y,l,w,conf,density]**（裂纹位置+长宽+置信度+密度）。
**实验结果（消融实验暴露硬伤）**：
- **仅时序分支 R²=0.0374**——用数据证实了 v2 的质疑：时序几乎没有信息量；
- 完整模型 R²=0.9440 反而低于“去掉单调性约束”的 0.9687——mono 损失在拖累精度；
- 单调违反率 34.8%~54.5%——一半的预测仍违反物理。
**升级原因**：6 维向量定位能力不足 + 融合架构与物理约束相互打架，需要工程化稳定版本来做受控实验。

###  **项目申请书和论文停留在此**

### v4（2026-08 上旬，稳定版 v4.6.12）：工程化加固与受控对比
**做了什么**：从 v3 fork，进入纯工程迭代——5 个骨干变体（resnet18/swin_yolo/vit_yolo/detr/swin_yolo_patchtst）×3 种任务模式（检测/分割/多任务），team_train 13 任务协作、断点续训，v4.0.0→v4.6.12 修了 20+ 个 bug（有 CODE_BUGS.md 记录）。损失函数定型为 `MultimodalCrackLoss = λ₁·MSE + λ₂·L_mono + λ₃·L_loc + λ₄·L_conf`。
**实验结果（在真实参数化扫描数据上）**：
- Concat 融合最好也只有 **R²=0.6508**；
- **完整 Cross-Attention 融合 R²=-0.2599**——评估报告原文：“负值，说明**多模态融合失败**”；
- ViT 变体 R²=-5.63；
- 单调违反率仍 ~49%。
**升级原因**：v4 的受控实验证明了两件事——**换成更真实的数据后，v3 架构的指标大幅崩塌**（仿真简化数据上的高分是幻觉）；6 维向量的输出形式画不出裂纹轨迹，工艺师看不懂模型在说什么。需要换输出范式和仿真体系。

### v5（2026-08 下旬，现行版本 v5-α 5.0.7）：范式重构
**做了什么**（README 差异表，每一条都对应 v4 的一个教训）：
| 维度 | v4 | v5 | 对应教训 |
|---|---|---|---|
| 输出 | 6 维向量/掩膜 | **8-16 动态关键点 + bbox**（Catmull-Rom 样条轨迹，可在图上画出来） | 6 维画不出轨迹、不可解释 |
| 输入 | 温度时序+场 | **温度场+应力场+热力图** 3 模态 | 时序分支 R²=0.037 被证实无信息量 |
| 物理约束 | 单调性损失（与精度打架） | **GP 嵌入模块 + 泊松先验** | v3 消融证明 mono 拖累精度 |
| 仿真 | 简化单向热传导 | **多方向热交换+辐射+应力松弛+三段曲线** | 简化数据导致 v4 指标幻觉 |
| 主损失 | 多类损失堆叠 | Catmull-Rom 样条 + Hausdorff 覆盖距离 | 输出形状决定损失形状 |

**现状（诚实盘面）**：V5A1-V5A5 完成（101/101 测试通过）；**V5A6（5 变体完整训练评估）尚未启动**，benchmark 为空；已知问题清单 V5-010（纯仿真无真实 GT）/V5-012（Griffith 简化）/V5-014-015（GP 归一化 train/eval 不一致）/V5-020（Streamlit 未装）——**这些已知问题正是窑智烧方案里逐条要修的**（GP bridge 修了 014/015，Gappy POD 用的就是 GP，真实数据靠学校窑标定）。**2026-09-29 补**：完成比赛副本回填与 GT 满面诊断战役（见下方 v5.0.8-alpha 补记）——版本保留在 v5.x.x 序列，不跳 v6。

### 给组长的三句话总结

1. **v2→v5 每一步都是被实验数据逼出来的**：v2 假考题（公式生成数据）→ v3 用消融证明时序无信息量（R²=0.037）→ v4 用真实数据证明融合失败（R²=-0.26）→ v5 换范式。
2. **“单模态温度时序推裂纹”这条路线在 v3 就被我们自己的消融实验证伪了**（时序分支 R²=0.0374），v5 升级为多模态场输入正是这个结论——所以新计划书里不能把 PE-TSNet 单时序路线写成“已验证可行”。
3. **这些演进直接决定了窑智烧的架构**：GP 不确定性（C3）来自 v5 GP 模块、物理约束显式（C2）来自 v2-v4 单调性损失的教训、多测点温度场重构（Gappy POD）正是对“单点时序信息不足”的正面回答——**每次升级的教训都变成了新方案的约束条件**。

⚠️ 一个提醒：之前文档里写过"不可解释导致训练暂停""6 维向量画不出轨迹"这类表述，考古结论是**全家族文档里没有这些原文**——最接近的证据是 v4 评估报告"多模态融合失败（R² 负值）"和会议决策 K7（输出改为位置+形状+轨迹）。给组长讲可以用"6 维向量定位能力不足、工艺上无法使用"这类有依据的说法，别引用没有出处的"训练暂停"典故。

### v5.0.8-alpha（2026-09-29，保留在 v5.x.x 序列，不跳 v6）：比赛副本回填 + GT 满面诊断战役

> 背景：2026-09-24~09-28 比赛期间在 `projects/new_project2316/assets/` 建立各项目独立副本继续开发（比赛仓库冻结），赛后回填原仓库。以下记录这场"平台解诊断"战役的完整因果链——**每个结论都带实验出处，全部脚本在 `projects/pe_mmnet/project_v5/_exp_*.py` 与 `_diag_*.py` 可复查**。

#### 事件链（按时间序，每步"为什么"）

1. **默认曲线口径训练出现平台解**：assets 副本跑默认烧成曲线（11.17h 物理口径，th=11 MPa，128px，1000+200 样本）150ep，loss≈1.0 平台不动。checkpoint 推理诊断（`_diag_plateau.py`）：kpts 塌缩在 [0,1] 角点、跨输入方差 0.0007（≈对输入不敏感）、样条出界。
2. **归因曾被纠偏**：最初判断"优化塌缩"，外部 AI 指出"loss 在奖励这个解"——验证后对方方向正确，且进一步挖出比其质疑更根本的两个 bug。
3. **loss 三缺陷定量证实（`_diag_negpad.py`）**：① trainer 算了 pixel_mask 没传 loss——负样本 (-1,-1) padding 全进 chamfer（2正6负 batch = 9 万假像素）；② 单向 chamfer 奖励"摊开覆盖"平凡解（边界角点 0.0148 < 真关键点 0.0925）；③ kpts 只有"样条→chamfer"双重间接监督（梯度病态）。修复：mask 透传 + 双向 chamfer + kpt_direct（权重 0.5）。
4. **但 GT 本身是坏的（更致命）**：th=11 下 281 个"正样本"中 250 个（89%）裂纹像素占 93.85% 面积——整屏超阈成面，真线状仅 31 个。**根因：阈值扫描只数"有像素即正样本"，没验 GT 形态**（方法论教训，已入验收纪律）。
5. **空间结构来源的排查战役（决定性实验链）**：
   - **路线 A 证伪**（`_exp_hotspot_linearity.py`）：初温局部扰动（热点/冷线/热线）×th 扫描，全部出团块。机制：MaxwellStress 是逐像素标量模型（无空间耦合），热扩散 fast 全程即抹平 61px @128（默认曲线 907px，抹平更彻底；dt 由 CFL 决定与曲线无关，p128 恒 0.039s）。
   - **周期边界对照证伪**（`_exp_periodic_bc.py`）：把 Robin 边界换成周期边界+体积源项（"观察窗"假设的彻底版），应力场几乎完全均匀（p50≈p99，方差 <2 MPa），任何 th 都满面（93.85%，恰与缓存实测互证）。**结论：本仿真器空间结构唯一来源是边界热流的几何；逐像素模型把平滑温度场映射为平滑应力场，线状不会自然涌现。**
   - **路线 C 可行**（`_exp_strength_field*.py` 三轮）：GT 判据改 σ_max > th×s(x,y)（窄深强度弱化通道 w=2px, δ≥0.9）+ 边缘 margin=12px 排除（边界应力框永远碾压线状成为最大连通域——单靠弱化场不够）。10 组合出线状（elong 3.2~5.3）。物理叙事口径：**仿真 GT 层面的线状先验注入，非物理自然涌现**。
   - **路线 D 可行且叙事更诚实**（`_exp_boundary_modulation.py`）：边界 h 空间调制（出风口/窑车接缝物理对应）。**整边 h×4 出线状**（th=50 面积 17.9%、elong 4.28，热冲击裂纹垂直温度梯度的经典机制）；局部凸包（×3~×10）全部失败（只产生局部斑点）。
   - **D' 随机化 50→100 样本统计 + 两道安全网验证（2026-09-29，`_exp_boundary_dprime.py`/`_exp_dprime_loss_ranking.py`/`_exp_field_cache_sweep.py`）**：外部 AI 复核指出 D3 单配置单样本风险，D'（随机边+段中心+段长+强度{2,3,4}）后判据 1/2 全过。安全网两道：①**loss 可学性零成本验证 30/30 PASS**（真kpts 0.07~0.16 << 随机 0.47~1.13 << 角点 0.79~2.37，chamfer_ub p90=0.023 紧凑，GT 关键点两两 chamfer p50=0.49 非塌缩）；②**th 细扫暴露口径事故**——首版细扫用裸阈值 (σ>th)，与产线 `_extract_crack_mask`（最大连通域+闭运算）数字不可比（th40 裸 59% vs 产线 79%），险些据假表换阈值；σ 场落盘后离线重扫产线口径：**th=40 线状 79/100（外推 790）、th=45/50 达 86-87（外推 860-870）**，与 50 样本统计一致。**附带发现**：scipy `binary_closing` 默认 border_value=0 会腐蚀贴边细线（seed 4215 裸 95px→闭运算 0px，52% 像素贴 x=127 边；th≥55 每档 7/100 被删光）——高阈值下正样本流失的真实机制。**诚实保留**：线状方向只有 H/V（平行调制边），需用户明确接受；全部统计基于 fast 曲线 128px，默认曲线（11.17h）下边界调制是持续边界条件理论上应存活，但**未实测**——全量生成前须 10 样本 spot check。
6. **loss 语义三形态验证**（`_exp_loss_semantics_v2.py`）：修复后 loss 在线状（真kpts 0.057 < 随机 0.482 ✓）和团块（0.351 < 0.449 ✓）GT 上排序正确；满面 GT 反转（随机 0.216 < 真值 0.314）——**已定性为 GT 语义问题而非 loss 缺陷**（"覆盖全场"语义下随机点本就更均匀，loss 奖励了该奖励的解）。此条引用时不得作为"loss 病态"证据。
7. **回填与固化**：比赛副本改动分两笔 commit 固化后回填三处原仓库（pe_mmnet 8 文件 + 回归 102 测试——原仓库 CHANGELOG 记为 v5.0.8-alpha 补丁版本，**保留在 v5.x.x 序列，不跳 v6**；monitor 安全配置化 9 文件；system test 路径自定位）。三桥路径改动**未回填**（副本层级差异所致，原层级本来就对）。

#### 本阶段新教训（延续 v1→v5 的"被数据逼出来"主线）

- **平台解≠优化失败**：模型学到的是对错误教育的精确拟合。看到 loss 平台先问"loss+GT 在奖励什么解"，再问"优化器为什么找不到好解"。
- **阈值扫描必须报 GT 形态**：只数 n_px>0 会把满面当成正样本（89% 伪正样本率的事故根因）。
- **验证一个"显然"的假设可能推翻它**：周期边界实验本是外部 AI 提议的"更物理"方案，实验结果是更糟（消除唯一空间结构来源）——假设要靠实验裁决，不靠物理直觉的合理度。
- **修复方案不必互斥**：区域级 GT 快速闭环（loss 已验证可用）是所有线状路线的共同验证基础，可先行；线状升级（D/C 组合）闭环后再投入。
