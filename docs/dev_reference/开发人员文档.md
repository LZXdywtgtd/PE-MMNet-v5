### 0.1 v5-α 模型变体（V5A4）

| 变体 | 架构 | 输出 |
|------|------|------|
| `PETSNetMultimodalV5` | ResNet-18 + CrossAttentionFusion + **SplineHead + GP** | dict {bbox, keypoints, validity, K, gp_lml?} |

| `ViTYOLOFPNV5` | ViT-Small + YOLO-FPN + TemporalFeatureExtractor + SplineHead + GP | 同上 |

### 0.2 v5-α 输入输出（与 v4 不同）

| 项 | v4 | v5-α |
|---|---|---|
| 输入图像通道 | 2（温度场 + 应力场） | **3**（温度场 + 应力场 + 热力图） |
| 输入 1D | (B, 300) 温度序列 | 同 v4 |
| 输出 | 6 维向量 `[x, y, l, w, conf, density]` | **dict** {bbox (B,4), keypoints (B,K,2), validity (B,K), K (B,), gp_lml?} |
| K | n/a | 动态 8-16 |

### 0.3 v5-α 训练循环（V5A5）

```
PatchDatasetV5 (仿真缓存) → collate_v5 (变长 padding)
   ↓
TrainerV5._train_step
   ↓
PatchAugmentorV5 (可选 CPU 增强)
   ↓
create_v5_model(variant)(x_1d, x_2d) → dict
   ↓
OrderedKeypointLoss(pred_bbox, pred_kpts, true_bbox, true_crack_pixels, gp_module)
   ↓
CSVHistory.log() + save_checkpoint(best/latest)
```

详细 API 见 [api.md §0](api.md#0-v5-α-新增apiv5a1-v5a5)。

## 一、项目概述

### 1.1 物理背景

日用陶瓷在热震过程中产生裂纹。基于格里菲斯断裂准则：
- 裂纹密度随温度下降单调递增
- 裂纹不可逆
- 裂纹位置与应力集中区域相关

### 1.2 输入输出

| 任务模式 | 输入 | 输出 |
|----------|------|------|
| Detection (v4) | 温度时序 + 温度场 + 应力场 | 6 维向量 `[x, y, l, w, conf, density]` |
| Segmentation (v4) | 同上 | 256×256 二值掩膜 |
| Multitask (v4) | 同上 | 检测向量 + 分割掩膜 |
| **v5-α** | **温度时序 + 温度场 + 应力场 + 热力图** | **dict {bbox, keypoints, validity, K, gp_lml?}** |

### 1.3 模型变体（v4 + v5-α 共存）

| 变体 | 架构 | 显存 | 等级 |
|------|------|------|------|
| `resnet18` | ResNet-18 + Cross-Attention | ~2 GB | L1 |
| `swin_yolo` | Swin-Tiny + YOLO-FPN + Cross-Attention | ~4 GB | L1+ |
| `vit_yolo` | ViT-Small + YOLO-FPN + Cross-Attention | ~3 GB | L1 |
| `swin_yolo_patchtst` | Swin-Tiny + YOLO-FPN + PatchTST | ~4 GB | L1+ |
| `detr` | ResNet-18 + Transformer + Cross-Attention | ~5 GB | L1+ |
| 消融 5 个 | 1D/2D/Concat/Add/CrossAttn | ~1-2 GB | L1 |
| **v5-α 5 变体** | 同上骨干 + SplineHead + GP | 同上 | L1+ |

## 四、模型架构详解

### 4.1 PETSNetMultimodal（`resnet18`）

```
1D 分支：(B, 300) → Micro+Macro+SelfAttn → 64 维
2D 分支：(B, 2, H, W) → ResNet-18 → 512 维
融合：CrossAttentionFusion(512, 64) → 576 维
输出：MultiTaskHead(576→6) → [x, y, l, w, conf, density]
```

### 4.2 SwinYOLOFPN（`swin_yolo`）

```
1D 分支：TFE → 64 维
2D 分支：(B, 2, 512, 512) → Swin-Tiny → (B, 768, 16, 16) → yolo_proj → (B, 256, 16, 16)
YOLO head：(B, 256, 6)
融合：CrossAttentionFusion(6, 64)
输出：MultiTaskHead(70→6)
训练返回 (B, 256, 6)；推理取 argmax(conf) 后融合
```

### 4.3 ViTYOLOFPN（`vit_yolo`）

类似 SwinYOLOFPN，骨干换 ViT-Small。Grid 动态：`max(16, image_size//32//4 * 4)`。

### 4.4 SwinYOLOFPNWithPatchTST（`swin_yolo_patchtst`）

TFE 换为 PatchTST1D（patch_len=10, d_model=64, 2 层 4 头）。其余同 SwinYOLOFPN。

### 4.5 DETRStyle（`detr`）

```
1D 分支：TFE → 64 维
2D 分支：(B, 2, H, W) → ResNet-18 + set_spatial_output=True → (B, 512, H/32, W/32)
位置编码 + flatten → (B, N, 512)
Transformer Encoder (6 层) + Decoder (100 queries)
DETRHead → (B, 100, 6)
训练：Hungarian 匹配选最佳 query → query_proj(6→128) → fusion(128, 64) → output_head(192→6)
loss = HungarianLoss + 0.5 × SuperviseLoss
```

## 五、训练/推理模式设计

所有新变体（swin_yolo/vit_yolo/detr/swin_yolo_patchtst）用 `self.training` 区分：

```python
if self.training:
    return raw_pred, global_density  # 训练：返回原始预测给 loss
else:
    # 推理：取最佳预测 → 融合 → 输出头
    output = self.output_head(self.fusion(best_pred, feat_1d))
    return output, global_density
```

**关键原则**：
- 训练模式：返回原始预测（供损失函数使用）
- 推理模式：经过融合+输出头（用于实际预测）

| 参数 | 说明 |

### 9.3 检查点完成状态机制

完成判定：`is_complete=True` **或** `is_retrain_done=True`。

**关键函数**：

- `get_completed_tasks()` —— 扫 `*_best.pt` 找已完成
- `_get_task_checkpoint_info(task_id)` —— 返回 `{epoch, best_epoch, last_epoch, is_complete, path}`

**续训匹配策略（v4.6.11+）**：

- 严格匹配 `task_id`
- 失败时按 `(variant, subdir, predict_offset)` 模糊匹配

### 9.4 配置签名校验

`SIGNATURE_KEYS`（`run_train.py:1198-1202`）含 **12 个关键字段**：

| 字段 | 说明 |
|------|------|
| `variant`, `backbone_2d`, `backbone_1d`, `fusion` | 模型架构 |
| `task`, `predict_offset` | 任务模式 / 时间偏移 |
| `triple_channel`, `use_coord_attn`, `staged_train` | 训练策略 |
| `feature_len`, `seq_interp_mode`, `remove_contours` | 数据处理 |

**DETR 额外**：`_DETR_SIGNATURE_KEYS = SIGNATURE_KEYS + ['image_size']` = 13 字段。

> **不在签名里**：`fp16`/`epochs`/`patience`/`lr`/`batch_size` —— 运行时参数变更不影响权重兼容性。

### 9.5 Epoch 目标数变更

| 场景 | 行为 |
|------|------|
| 150 epoch 早停在 85，下次想跑 200 | 自动从 85 继续 |
| 跑了 3 epoch 测试，下次想跑 100 | 自动从 3 继续 |
| 跑完了 150 epoch，下次想跑 200 | 自动从 150 继续 |
| 跑完了 150 epoch，只想跑 100 | 直接返回（已达目标） |

### 9.6 检查点加载行为

| 检查点状态 | 配置签名 | 目标 Epoch > 已训练? | 行为 |
|-----------|----------|---------------------|------|
| `is_complete=True` | 匹配 | 是 | 继续训练（`start_epoch = saved_epoch`） |
| `is_complete=True` | 匹配 | 否 | 直接返回（`is_complete=True` 即完成） |
| `is_complete=False` | 匹配 | 任意 | 续训 |
| 任意 | 不匹配 | 任意 | 备份 + 强制重训 |
| 不存在 | — | — | 从头训练 |

## 十、添加新模型变体

### 10.1 步骤

1. 在 `models/` 中新建 `<feature>.py`，定义 `nn.Module` 子类
2. 实现 `forward(seq_1d, img_2d) -> (output, global_density)`
3. 如要 `self.training` 区分模式：训练返回原始预测，推理返回融合后预测
4. 在 `run_train.py` 的 `VARIANT_MODELS` 字典注册
5. 如需新损失，在 `training/mono_loss.py` 加类，并在 `train_model` 选择逻辑中加分支
6. 在 `run_train.py:2424` 的 `--variant` choices 加新 key
7. 更新架构文档 + API 文档

### 10.2 示例

```python
class MyNewVariant(nn.Module):
    def __init__(self, seq_len=300, image_size=256, dropout=0.2):

            return raw_pred, global_density
        else:
            # 推理：取最佳预测 → 融合
```

## 十二、常见问题排查

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| `CUDA: False` | GPU 驱动/版本不匹配 | 见 [CUDA 安装指南](../user_guides/CUDA安装指南.md) |

| 续训从 epoch 1 重数 | 旧版 `train_model` 未接 `start_epoch` | 升级到 v4.6.10+ |
| 已完成任务被重跑 | 老 checkpoint `task_id` 不匹配 | v4.6.11 fuzzy match 已认主；如仍出现见 [CODE_BUGS.md B008](../CODE_BUGS.md) |

## 十三、代码规范

### 13.1 命名规范

- 类：`PascalCase`（`PETSNetMultimodal`, `CrossAttentionFusion`）
- 函数/变量：`snake_case`（`train_model`, `best_loss`）
- 常量：`UPPER_SNAKE`（`NEW_VARIANTS`, `SIGNATURE_KEYS`）
- 私有函数：`_leading_underscore`（`_build_checkpoint_data`, `_check_signature_mismatch`）

### 13.2 训练/推理模式

- 训练：`model.training=True` → 返回原始预测
- 推理：`model.training=False` → 返回融合后预测
- 不要在 `forward` 内部改 `.train()` / `.eval()`

### 13.3 工具脚本存放规范

- `tools/` 下的脚本**独立可运行**（`python tools/foo.py`）
- 用 `argparse` 接收参数，**不要 import 项目内部模块**（除非必要）
- 输出路径用 `Path(__file__).resolve().parent.parent` 推导项目根

### 13.4 Windows 兼容性

- 路径用 `pathlib.Path`，避免 `os.path.join` + 字符串拼接
- 跨平台 shell 命令用 `subprocess.run(args_list, shell=False)` 而非 `os.system(cmd_string)`
- 控制台输出用 `sys.stdout.reconfigure(encoding='utf-8', errors='replace')` 防止 GBK 崩溃

### 14.3 Windows 兼容性

启动时：

```python
if sys.platform == 'win32':
    try:
        sys.stdout.reconfigure(encoding='utf-8', errors='replace')
        sys.stderr.reconfigure(encoding='utf-8', errors='replace')
    except Exception:
        pass
```

避免 GBK 编码崩溃。进度条字符 `#/-` 替代 `█/░` 也是为了 Windows GBK 兼容。
