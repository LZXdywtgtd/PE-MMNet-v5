# PE-MMNet v4 架构设计文档

> 版本：4.6.11 | 更新：2026-08-12
>
> ⚠️ **本文档描述 v4 架构**。v5-α 架构详见 [`docs/v5_架构设计.md`](../v5_架构设计.md)。
>
> v5-α 关键改动：
> - 输出头：v4 的 6 维向量 / YOLO 网格 / DETR queries → **SplineHead**（bbox + 8-16 关键点）
> - 物理约束：v4 的单调性损失 → **GP 嵌入模块 + GP LML 正则**
> - 输入通道：v4 的 2 通道 → v5-α 的 3 通道（温度场 + 应力场 + 热力图）
> - 训练循环：v4 的 `run_train.py` → v5-α 的 `run_train_v5.py` + `trainer_v5.py`

## 三、模型变体详解

### 3.1 基础模型：PETSNetMultimodal（`resnet18`）

```
输入
├── 1D 分支：(B, 300) 温度序列
│   ├── Micro1DCNN → 局部特征 (32 维)
│   ├── Macro1DCNN → 全局趋势 (32 维)
│   ├── Multi-Head Self-Attention → 通道融合
│   └── 输出：64 维向量
│
└── 2D 分支：(B, 2, H, W) 温度场+应力场
    ├── ResNet-18（ImageNet 预训练）
    │   └── 输出：(B, 512, H', W')
    └── GlobalAvgPool → (B, 512) 向量

融合：CrossAttentionFusion(dim_2d=512, dim_1d=64)
输出：MultiTaskHead(576→6) → (B, 6) [x, y, l, w, conf, density]
```

**显存占用**：~2 GB（batch=4，FP16=✗ 因 NaN 风险）

### 3.2 SwinYOLOFPN（`swin_yolo`）

```
输入
├── 1D 分支：TemporalFeatureExtractor → 64 维
│
└── 2D 分支：(B, 2, 512, 512)
    ├── SwinBackbone2D（timm Swin-Tiny，img_size=512）
    │   └── 输出多尺度特征，取最后一层 (B, 768, 16, 16)
    ├── yolo_proj：Conv2d(768→256) + BN + ReLU
    └── YOLOFPNHead → (B, 256, 6)

融合：CrossAttentionFusion(dim_2d=6, dim_1d=64)
输出：MultiTaskHead(70→6) → (B, 6)

训练模式：返回 (B, G², 6) 完整网格预测（G² = 16² = 256）
推理模式：取最高 conf 网格 → fusion → output_head → (B, 6)
```

**grid_size**：固定 16（硬编码），即固定 256 个网格预测。

**显存占用**：~4 GB（batch=4，FP16=✔）

### 3.3 ViTYOLOFPN（`vit_yolo`）

```
输入
├── 1D 分支：TemporalFeatureExtractor → 64 维
│
└── 2D 分支：(B, 2, 任意尺寸) 图像
    ├── input_resize：Conv2d(2→3, kernel_size=1) + BN + ReLU
    ├── ViTYOLOBackbone2D（timm vit_small_patch16_224）
    │   └── 输出：(B, 256, 7, 7)
    ├── interp：Resize 到 (16, 16)
    ├── fpn：Conv2d(256→256, kernel_size=3) + BN + ReLU
    └── YOLOFPNHead → (B, 256, 6)

融合：CrossAttentionFusion(dim_2d=6, dim_1d=64)
输出：MultiTaskHead(70→6) → (B, 6)
```

**grid_size 动态计算**：`max(16, (image_size // 32 // 4) * 4)`，确保适配 YOLO head。
- 256×256 → 16
- 512×512 → 16
- 1024×1024 → 20

**显存占用**：~3 GB（batch=4，FP16=✔）

### 3.4 SwinYOLOFPNWithPatchTST（`swin_yolo_patchtst`）

```
输入
├── 1D 分支：(B, 300) PatchTST1D
│   ├── PatchEmbedding：patch_len=10 → 30 patches, d_model=64
│   ├── 可学习位置编码
│   ├── Transformer Encoder（2 层，4 头）
│   └── 输出：64 维向量
│
└── 2D 分支：(B, 2, 512, 512)
    ├── SwinBackbone2D（timm Swin-Tiny）
    │   └── 输出多尺度特征，取最后一层 (B, 768, G, G)
    ├── yolo_proj：Conv2d(768→256)
    └── YOLOFPNHead → (B, G², 6)
```

**grid_size 动态计算**：同 ViT YOLO。

**优势**：
- PatchTST 比 TemporalFeatureExtractor 更适合长序列
- Patch 机制捕获局部时序模式
- Transformer 全局注意力捕获长程依赖
- 有 fallback 机制（导入失败时使用 TFE）

**显存占用**：~4 GB（batch=4，FP16=✔）

### 3.5 DETRStyle（`detr`）

```
输入
├── 1D 分支：TemporalFeatureExtractor → 64 维
│
└── 2D 分支：(B, 2, H, W)
    ├── ResNet18Backbone2D（启用 set_spatial_output=True）
    │   └── 输出：(B, 512, H/32, W/32) — 8×8 for 256x256
    ├── input_proj：Conv2d(512→512)
    ├── PositionalEncoding2D：动态匹配特征图尺寸
    ├── flatten + transpose → (B, 64, 512)
    ├── TransformerEncoder（6 层）
    ├── DETRDecoder（100 个 Object Queries）
    └── DETRHead → (B, 100, 6)

训练链路：
  detr_pred (B, 100, 6)
  → Hungarian 匹配选最佳 query → best_query (B, 6)
  → query_proj(6→128)
  → fusion(dim_2d=128, dim_1d=64) → (B, 192)
  → output_head(192→6) → final_output (B, 6)
  loss = HungarianLoss(detr_pred) + 0.5×SuperviseLoss(final_output)
```

**显存占用**：~5 GB（batch=4，FP16=✔）

## 四、损失函数选择

`run_train.py:1462-1490` 的选择逻辑：

| 任务 | 变体 | 损失类 | 默认权重 | 目标分配 |
|------|------|--------|----------|----------|
| `segmentation` | 任意 | `SegmentationLoss` | lambda_dice=1.0, lambda_bce=0.5 | Dice + BCE |
| `multitask` | 任意 | `MultimodalSegmentationLoss` | lambda_seg=1.0, lambda_det=0.5 | 检测+分割联合 |
| `detection` | `swin_yolo` / `vit_yolo` / `swin_yolo_patchtst` | `YOLOLoss` + `YOLOTargetAssigner` | **硬编码** box=1.0, conf=1.0, mono=0.1 | 网格分配（dynamic grid） |
| `detection` | `detr` | `DETRLoss` + `HungarianMatcher` | **硬编码** bbox=1.0, conf=1.0, mono=0.1 | 最优匹配（100 queries） |
| `detection` | 其它（含 6 个消融变体） | `MultimodalCrackLoss` | mse=1.0, **mono=args.lambda_mono**, loc=1.0, conf=1.0 | 直接比较 6 维向量 |

> ⚠️ **`--lambda_mono` 仅对 6 个旧变体生效**。4 个新变体（YOLO 系列 + DETR）的损失构造器**硬编码** `lambda_mono=0.1`，CLI 参数被静默忽略（见 [CODE_BUGS.md B003](v5_宸茬煡闂.md)）。

## 五、训练/推理模式设计

所有新变体（swin_yolo/vit_yolo/detr/swin_yolo_patchtst）统一使用 `self.training` 属性区分模式：

```python
if self.training:
    return raw_pred, global_density  # 用于损失计算
else:
    # 取最佳预测 → 融合 → 输出头
    output = self.output_head(self.fusion(best_pred, feat_1d))
    return output, global_density
```

**关键原则**：
- 训练模式：返回原始预测（供损失函数使用）
- 推理模式：经过融合+输出头（用于实际预测）

## 八、检查点系统

### 8.1 文件命名

**新格式（v4.6.6+）**：`{base}_e{epoch:03d}_{best|last}.pt`

- `base = {task}_off{offset}`（不含 variant，variant 在目录名）
- epoch 用 3 位零填充：`e001`, `e008`, `e150`
- best 和 last 的 epoch 可能不同：val_loss 没改善时 best 保留之前的

**示例**：

```
checkpoints/detr/baseline/
├── detection_off0_e020_best.pt
├── detection_off0_e047_last.pt
```

**配套函数**：

- `_find_latest_epoch_file(base_path, ctype)` —— glob `{base}_e*_{ctype}.pt`，按 epoch 数字取最大
- `_delete_other_epoch_ckpts(ckpt_base, kind, keep_epoch, _known_files)` —— 删同 base 下其他 epoch 文件
- 保证每个 base 目录里**最多 1 个 best + 1 个 last**

**旧格式**（兼容但不再生成）：`{variant}_{task}_off{offset}_{best|last}.pt`（无 epoch 后缀）

### 8.2 双保险机制

| 文件 | 保存时机 | 用途 |
|------|----------|------|
| `e{N:03d}_best.pt` | val_loss 改善时（`< best_loss - min_delta`） | 评估 / 部署 |
| `e{N:03d}_last.pt` | 每个 epoch 结束无条件 | 断点续训 |

**为什么 best 和 last 分开**：
- best 用于评估（取历史最优）
- last 用于续训（取最新状态）
- 续训来源是 `last.pt`，更符合"断点恢复"语义

### 8.3 续训流程

```
启动训练
   ↓
train_variant: 查找 base_path = {ckpt_subdir}/{task}_off{offset}
   ↓
_find_latest_epoch_file(base_path, 'last') → save_path
   ↓
加载 checkpoint:
   is_complete = ckpt.get('is_complete', False)
   saved_epoch = ckpt.get('epoch', 0)         # 1-indexed
   best_loss = ckpt.get('best_loss', float('inf'))
   ↓
决策矩阵:
   is_complete=False → 从断点恢复 (start_epoch=saved_epoch)
   is_complete=True, target>saved → 继续训练 (start_epoch=saved_epoch)
   is_complete=True, target<=saved → 直接返回（已达标）
   签名不匹配 → 备份旧 ckpt + 强制重训
   saved_epoch >= target → 写 is_complete=True（v4.6.11 早返回）
   ↓
train_model(model, ..., start_epoch, best_loss)
   ├─ best_loss = best_loss  # 继承历史最优
   ├─ for epoch in range(start_epoch, config['epochs']):
   │   ├─ val_loss 改善 → 保存 e{epoch+1:03d}_best.pt
   │   └─ 每轮结束 → 保存 e{epoch+1:03d}_last.pt
   ├─ _delete_other_epoch_ckpts(ckpt_base, 'best', epoch+1)
   └─ _delete_other_epoch_ckpts(ckpt_base, 'last', epoch+1)
   ↓
_mark_checkpoint_complete(terminated_by_early_stop=...) → 写回 is_complete=True
```

**3 个关键状态必须透传**（v4.6.10 修复）：

| 状态 | 来源 | 不透传会怎样 |
|------|------|--------------|
| `start_epoch` | `ckpt.get('epoch', 0)` | 续训从 epoch 1 重数，保存 `e001_best.pt` 覆盖历史 |
| `best_loss` | `ckpt.get('best_loss', inf)` | 第一个 epoch 必然刷 best，污染历史最优 |
| `last_checkpoint_path` | 从 `checkpoint_path` 后缀推断 | 续训不保存 `_last.pt` |

### 8.4 元数据字段

```python
checkpoint = {

    'best_loss': 0.3806,

        'backbone_2d': 'resnet18',
```

### 8.5 配置签名校验

`SIGNATURE_KEYS`（`run_train.py:1198-1202`）包含 **12 个关键字段**，`_DETR_SIGNATURE_KEYS` = 13 个（额外加 `image_size`，因 DETR 位置编码依赖）。

**普通变体（12 字段）**：

| 字段 | 说明 |
|------|------|
| `variant`, `backbone_2d`, `backbone_1d`, `fusion` | 模型架构 |
| `task`, `predict_offset` | 任务模式 / 时间偏移 |
| `triple_channel`, `use_coord_attn`, `staged_train` | 训练策略 |
| `feature_len`, `seq_interp_mode`, `remove_contours` | 数据处理 |

**DETR 额外**（13 字段）：`image_size`

> **不在签名里**：`fp16`/`epochs`/`patience`/`lr`/`batch_size` —— 运行时参数变更不影响模型权重兼容性。

加载 checkpoint 时对 `config` 字典的字段做严格比对，**任意一个不匹配**就触发强制重训 + 备份旧文件。

### 8.6 续训匹配策略（v4.6.11+）

为支持任务合并（如 A4_long → A4），`_resolve_task_id` 双重匹配：

1. **严格匹配**：`ckpt['task_id']` 在 `all_tasks` 中
2. **模糊匹配**：`ckpt['config']` 的 `(variant, subdir, predict_offset)` 三元组匹配某个任务

第一个匹配的 task_id 胜出。

### 8.7 备份目录规范

```
checkpoints/backup/
├── _save_reason_fix_YYYYMMDD/        # tools/fix_save_reason.py 修复时的原文件
├── _ckpt_cleanup_YYYYMMDD/           # tools/cleanup_old_ckpts.py 清理时的中间文件
├── _dev_scripts_YYYYMMDD/            # 临时调试脚本（_sim_*.py / _verify_*.py）
└── _buggy_ckpt_names_YYYYMMDD/       # 错命名检查点（_last.pt_best.pt 拼接等）
```

> 命名约定：`_purpose_YYYYMMDD/`，方便追溯历史操作。

### 8.8 幂等性（v4.6.11+）

`_mark_checkpoint_complete()` 加了 guard：已是目标状态（`is_complete=True` + 正确 `save_reason` + 正确 `task_id`）则跳过 `torch.load` + `torch.save`，节省数百 MB I/O。允许重复运行 `team_train.py --auto` 不会无谓重写 checkpoint。
