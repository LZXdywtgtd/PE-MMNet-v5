## 〇、v3 重写说明（为什么整份重写）

v2 及之前的核心叙事是"位置回归头全局失败（42% failed + 镜像
错位 + 向图心收缩），需要 FPN+位置头去救"——**这个叙事的评估
基础被 rot90 增广 bug 污染**：

- 训练时 50% 样本被 rot90 后标签转了 180°（图像顺时针、标签
  逆时针），模型见到的"裂纹在底"配图是"裂纹在顶"的标签
- 一个 bug 同时解释：混淆矩阵完美反对角（99% 对侧）、failed/
  learned 双峰但各自内部一致（模型对两个自洽子集各学各的）、
  heatmap 热区正确但 pred 飘对侧、learned 组 32% 顺序错（轻度
  污染：点在正确侧但个别点被拉向对侧）
- 修复后**全部现象消失**：failed 0%、对侧占比无、learned 组
  px 误差 14.8/17.8px → 1.6/1.2px（离群点也消失）

**作废结论清单**（引用时以本清单为准）：

| v2 结论 | 现状 |
|---|---|
| "位置回归头全局失败，需要 FPN+位置头"（§二/§三主线动机） | **作废**——失败是增广 bug 人为产物 |
| "向图心收缩"叙事（选项 C H5） | **重新定性**——贴边裂纹镜像的几何旁效（pred 飘对侧后离图心更近），非独立机制 |
| "粗大型簇无独立机制，两簇=位置回归未收敛的连续谱"（选项 C） | **部分作废**——两簇差异当时真实存在，但其"未收敛"判定是 bug 产物；两簇形态学描述仍有效 |
| "learned 组 32% 顺序错，顺序监督上界 ~31 样本"（第五轮/§三辅线 1） | **作废**——顺序错也是 rot180 污染，修复后离群点消失，无需顺序监督救 |
| "train 同病 35% = 全局结构瓶颈（4×4 粒度不可表达）" | **作废**——train 同病同样是增广污染 |
| "修复增广后塌缩为平台解"（第十轮一度误判） | **作废**——augfix1 漏 `--cache_dir` 在 stock 数据上训练，非修复的因果 |

**保留有效的结论**（不受增广污染或已重新验证）：

- loss 三修（负样本 padding 掩蔽、双向 chamfer、kpt_direct 直接
  监督）——这些修复针对 loss 语义，与增广无关
- GT 生成修复（V5-024/027/028）
- oracle 曲线（GT 已知时分辨率收益：8×8=59% / 16×16=93% /
  32×32=90% 折线退化）——oracle 用 GT 位置算，与模型无关
- 判据 3 过（44 倍余量）——修复后 inter_var 0.0718→0.2228 仍过
- 工程基建（断点续跑/多进程/缓存）、bbox 活性、样条零出界、
  106/106 回归

| failed 率（>60px） | 0% | **0%** |

**augfix2 的 93%→干净 GT 100% 的差值解释**（V5-033）：历史训练
链加载的缓存键无 D' 后缀 → 实际用的是剥框前旧 GT——augfix2
的 93% 里 11/200 L 形污染样本模型"全败"的根因=学的就是框上走
的 GT。缓存换血（旧 GT 备份 OLDGT_ 前缀 + 干净 dp npz 复制为
无后缀名）+ 重训后污染样本消失，通过率自然到 100%。

**残余结构**：仅 idx=101 为坏 GT（骨架崩塌在 2×7px 角落而 mask
蔓延 101×29px，V5-034 P2）——其 pred chamfer 2.0px"通过"是双向
chamfer 被大团块稀释的假象（pred 学到真团块形态=正确，坏 GT
被放行）。196 干净全过 + 1 坏 GT 稀释放行，不阻塞 v5-β。

```
--variant resnet18 --epochs 150 --patch_size 128 \

```

val seed 434242（=train+10000，trainer 硬编码）；~11s/ep（缓存
命中）。**干净 GT 口径新增 `--train_seed 424242`**（V5-033：
data seed 与 train_seed 分离，换训练 seed 必传，否则缓存键含
seed miss → 静默现场仿真 stock 数据）。

**V5-031 新增纪律（违者数字无效）**：

1. `--cache_dir` **必传**——漏传时静默现场仿真（stock 分布），
   训练/评估分布错位且 val 数字自洽（augfix1 事故：150ep 在
   stock 上训，val_coverage=0.0218 看似正常，实为 38/50 负
   batch 稀释后的假低值；复刻验证 `_diag_stock6x.py` 逐位
   复现 0.021843）
2. **训练/离线数字差 >3 倍先查数据分布**——augfix1 的 0.0218
   （训练）vs 0.1410（复测）vs 0.5776（D' 离线）三数字对不拢
   是数据错位的暴露点；已实现启动断言（见 §九）
3. **负 batch 稀释**：coverage_loss 全负 batch 返回 0 且 eval
   均值计入 0 → val_coverage 受正样本率稀释，跨数据集比较时
   必须同时报告正样本数与正 batch 占比

**V5-033 新增纪律（违者数字无效）**：

4. **训练链实际加载的 GT 口径必须显式核验**——缓存键无变体
   标记期间（P0 根治前），任何训练前先确认 `logs/sim_cache/`
   无后缀 npz 的 GT 与 `_dp.npz` 一致（或抽查 L 形扫描）；
   augfix2 的 93% 即此事故的存量数字
5. **换 seed 只用 `--train_seed`**，不动 `--seed`（后者进缓存键）
