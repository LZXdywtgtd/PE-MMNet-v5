## 一、系统概述

`team_train.py` 是一个配置驱动的团队任务分发系统，让团队成员无需了解复杂的命令行参数即可参与训练。

### 核心功能

| 功能 | 说明 |
|------|------|
| **配置驱动** | 任务由 JSON 配置文件定义，协调者分发 |
| **依赖管理** | 前置任务未完成自动锁定，拓扑排序执行 |
| **硬件感知** | 检测 GPU 显存，自动判断任务适配性 |
| **状态可视化** | 已完成/可执行/警告/锁定 状态显示 |
| **检查点导入** | 支持导入队友的检查点文件 |
| **自动批量执行** | 按拓扑排序执行所有可执行任务 |
| **断点续训** | 任务意外中断后从 `last.pt` 自动恢复 |
| **训练历史** | CSV 按 task_id 分文件记录每个 epoch 指标 |
| **任务日志** | 记录每个任务的执行情况（JSON Lines） |

## 二、快速开始

### 2.1 Windows 一键启动（推荐）

```powershell
# 进入项目目录
cd D:\team_project\projects\pe_mmnet\project_v4

# 双击运行 run.bat（ASCII 启动器）
# 或 PowerShell 直接调
.\run.ps1
```

`run.bat` 内部调 `powershell -ExecutionPolicy Bypass -NoProfile -File run.ps1`，自动设置 UTF-8 编码、选 conda `pe_mmnet` 环境的 python、运行 `team_train.py --auto`，输出 `tee` 到 `logs/cmd_run.log`。

### 2.2 命令行模式

```bash
# 交互式菜单
python team_train.py

# 自动执行所有可执行任务
python team_train.py --auto

# 强制执行（包括硬件警告任务，无需确认）
python team_train.py --auto --force

# 导入队友检查点
python team_train.py --import
```

> `team_train.py` 内部用 `subprocess.run(args, shell=False)` 调子进程，不会触发 Windows cmd.exe 的路径转义 bug。

### 2.3 界面说明

```
============================================================
  PE-MMNet v4 团队协作训练
============================================================

当前硬件等级: L3 (显存: 8.5GB)
已完成任务: 7/13

状态标记: [✓] 已完成 | [▶] 可执行 | [!] 硬件警告 | [🔒] 依赖未完成

  [ 1] ✓ ResNet18基线
       轻量级CNN骨干，所有优化的基准线
       [L] L1 | [T] ~12小时 | [G] ~2GB

  [ 2] ▶ DETR 150 epoch 完整训练
       DETR 完整 150 epoch 训练
       [L] L1+ | [T] ~18小时 | [G] ~5GB

  [q] 退出
```

### 2.4 状态标记

| 标记 | 含义 | 操作 |
|------|------|------|
| `✓` | 已完成（best.pt `is_complete=True`） | 自动跳过 |
| `▶` | 可执行（依赖满足+硬件适配） | 直接运行 |
| `!` | 硬件警告（显存可能不足） | 需确认后运行 |
| `🔒` | 依赖未完成（前置任务未跑） | 需先完成依赖 |
| `⏸` | 中断（有检查点但 `is_complete=False`） | 自动续训 |
| `?` | 未知 | 报告 bug |

## 三、协调者端操作

### 3.1 创建任务配置

在 `tasks/` 目录下创建 JSON 文件（**顶层必须是数组**）：

**示例：`tasks/team_baseline.json`**
```json
[
  {
    "id": "A1",
    "name": "ResNet18基线",
    "desc": "轻量级CNN骨干，所有优化的基准线",
    "subdir": "baseline",
    "args": "--variant resnet18 --epochs 150 --patience 30",
    "level": "L1",
    "time": "~12小时",
    "gpu_mem": "~2GB",
    "deps": []
  },
  {
    "id": "A4",
    "name": "DETR基线",
    "desc": "纯Transformer的DETR端到端检测，验证全局上下文感知",
    "subdir": "baseline",
    "args": "--variant detr --epochs 150 --patience 30 --lr 1e-4",
    "level": "L1+",
    "time": "~18小时",
    "gpu_mem": "~5GB",
    "deps": []
  }
]
```

**带依赖的任务：`tasks/team_optimization.json`**
```json
[
  {
    "id": "B1",
    "name": "门控融合优化",
    "desc": "基于ResNet18：温度/应力通道分治门控融合",
    "subdir": "gated",
    "args": "--variant resnet18 --fusion gated --epochs 150 --patience 30",
    "level": "L2",
    "time": "~15小时",
    "gpu_mem": "~2GB",
    "deps": ["A1"]
  }
]
```

> ⚠️ `{"tasks":[...]}` 包装形式会被**静默丢弃**（[CODE_BUGS.md B004](../CODE_BUGS.md)），必须用顶层数组。

### 3.2 字段说明

| 字段 | 必须 | 说明 |
|------|------|------|
| `id` | ✔ | 唯一标识，用于依赖引用 |
| `name` | ✔ | 显示名称 |
| `desc` | ✔ | 简短描述 |
| `subdir` | ✔ | 检查点子目录（baseline/gated/coord/staged/...） |
| `args` | ✔ | 命令行参数（拼到 `run_train.py --mode train` 后，空格分隔） |
| `level` | ✔ | 性能等级：L1 / L1+ / L2 / L2+ / L3（其它值不在菜单显示） |
| `time` | ✔ | 预计时间（自由文本，仅显示） |
| `gpu_mem` | ✔ | 预估显存（自由文本，仅显示） |
| `deps` | ✗ | 前置依赖任务 ID 列表 |

### 3.3 硬件等级

`get_hardware_level()`（`team_train.py:322`）按**总**显存分级：

| 等级 | 总显存要求 | 说明 |
|------|----------|------|
| L1 | < 4 GB | ResNet18 基线 |
| L1+ | 4-6 GB | YOLO 系列 / DETR |
| L2 | 6-8 GB | 优化变体（gated/coord/triple_channel/aug_cutmix） |
| L2+ | 6-8 GB | 分阶段训练 / 组合优化（**rank 同 L2**，[CODE_BUGS.md B007](../CODE_BUGS.md)） |
| L3 | ≥ 8 GB | 完整优化，大图 |

> ⚠️ L2+ 与 L2 同级（rank 3），L2+ 任务在 L2 机器上**不会**警告。

### 3.4 分发任务

1. 在 `tasks/` 目录创建配置文件
2. 将整个 `tasks/` 文件夹打包
3. 发送给组员
4. 组员解压到 `project_v4/` 根目录即可

### 3.5 模板文件（不会被加载）

`examples.json` / `example.json` / `template.json` 这三种文件名会被 `load_tasks_from_files()` 跳过——可放参考模板。

## 四、检查点导入

### 4.1 自动导入

将队友分享的 `.pt` 检查点文件复制到 `checkpoints/{variant}/{subdir}/` 目录，下次运行 `team_train.py` 时会自动识别。

### 4.2 手动导入

运行 `team_train.py`，选择 `[i]` 导入队友检查点，输入队友的检查点文件夹路径即可。

> ⚠️ `import_checkpoint`（`team_train.py:935`）会**复制到 `checkpoints/` 根目录**，不会自动按 variant/subdir 分类。如需手动归类，运行后 `mv checkpoints/foo.pt checkpoints/detr/baseline/detection_off0_*.pt`（[CODE_BUGS.md B009](../CODE_BUGS.md)）。

### 4.3 任务 ID 识别

`_resolve_task_id()`（`team_train.py:360`）双重匹配：

1. **元数据严格匹配**：从检查点的 `task_id` 字段读取
2. **配置三元组模糊匹配**：`ckpt['config']` 的 `(variant, subdir, predict_offset)` 与 `tasks/*.json` 中的任务匹配

支持的文件名格式：

- `detection_off0_e008_last.pt`（配合 `task_id` 字段识别）
- `detection_off0_e009_best.pt`

旧格式（仍兼容）：

- `{variant}_{task}_off{offset}_best.pt`
- `checkpoint_A1_best.pt`

## 五、自动执行模式

### 5.1 自动执行

```bash
python team_train.py --auto
```

按依赖顺序自动执行所有可执行任务。

### 5.2 强制执行

```bash
python team_train.py --auto --force
```

强制执行所有任务（包括硬件警告任务），无需用户确认。

### 5.3 流程

1. 检测所有可执行状态的任务
2. 按依赖顺序排序（拓扑排序）
3. 依次执行，遇到失败可选择继续或停止
4. 每次任务完成后刷新进度表（实时显示 `best:N/xxx last:N/xxx`）

### 5.4 进度表刷新（v4.6.6+）

`team_train.py` 启动时显示完整任务列表 + 依赖关系 + 检查点状态。**每次任务完成后实时刷新**，显示刚完成/刚解锁的任务。

## 六、断点续训

### 6.1 触发条件

当 `checkpoints/{variant}/{subdir}/` 下存在 `e{N:03d}_last.pt` 且 `is_complete=False` 时，下次启动 `team_train.py` 会自动从该 epoch 续训。

**实际日志**：

```
[OK] 检测到意外中断的检查点: ./checkpoints/detr/baseline/detection_off0_e008_last.pt (Epoch 8)
[RESUME] 从 Epoch 9/150 继续训练（已训练 8 轮）
Epoch 9/150 | Loss: 0.3859 (Best: 0.3806) | LR: 9.70e-05 | Time: 495.4s
```

### 6.2 续训机制详解

1. **`train_variant`** 加载 `last.pt`，算出 3 个状态：`saved_epoch`、`best_loss`、`is_complete`
2. **透传给 `train_model`**：`start_epoch=saved_epoch`、`best_loss=best_loss`
3. **`train_model`** for 循环从 `start_epoch` 开始
4. **每个 epoch** 保存 `e{epoch+1:03d}_best.pt` / `e{epoch+1:03d}_last.pt`
5. **跑完所有 epoch** 后 `_mark_checkpoint_complete(terminated_by_early_stop=...)` 写回 `is_complete=True`

详见 [架构设计文档 §8.3](../architecture/架构设计文档.md#83-续训流程)。

### 6.3 续训匹配策略（v4.6.11+）

支持任务合并场景（如 A4_long → A4 合并后，老检查点被新任务认主）：

- 严格匹配 `ckpt['task_id']` 失败时，按 `(variant, subdir, predict_offset)` 三元组模糊匹配
- 详见 [架构设计文档 §8.6](../architecture/架构设计文档.md#86-续训匹配策略v4611)

### 6.4 中断恢复

- **Ctrl+C 中断**：保存 `e{N:03d}_last.pt`，下次启动自动续训
- **崩溃/断电**：同上（每个 epoch 结束都会保存 last）
- **误 Ctrl+C**：删除对应 last.pt 重新训练（`--force_retrain`）

### 6.5 Epoch 目标数变更

| 场景 | 行为 |
|------|------|
| 150 epoch 早停在 85，下次想跑 200 | 自动从 85 继续 |
| 跑了 3 epoch 测试，下次想跑 100 | 自动从 3 继续 |
| 跑完了 150 epoch，下次想跑 200 | 自动从 150 继续 |
| 跑完了 150 epoch，只想跑 100 | 直接返回（已达目标） |

### 6.6 已训练 epoch ≥ 目标 epoch（v4.6.11 早返回）

`train_variant` 在续训前会检查 `start_epoch >= config['epochs']`：

- 是：直接调用 `_mark_checkpoint_complete(best_eval_path, save_path, ...)` 写回 `is_complete=True`，不进入训练循环（避免空循环导致 `is_complete` 写不回去）
- 否：进入正常训练循环

### 6.7 配置变更

**配置签名校验失败时自动强制重训**：旧检查点备份到 `checkpoints/backup/_a4long_resume_test_YYYYMMDD/`，新训练完成后 `is_complete=True` 写入。

不在签名字段里的运行时参数（`lr`/`batch_size`/`fp16`/`epochs`/`patience`）变更不会触发重训。

## 七、训练历史 CSV

### 7.1 位置

`logs/training_history/{task_id}.csv`

### 7.2 字段

```csv
timestamp,task_id,variant,subdir,predict_offset,epoch,train_loss,val_loss,best_loss,lr,epoch_time_s
2026-08-11T16:27:14,A4,detr,baseline,0,9,0.385854,0.380610,0.380623,9.701e-05,491.62
```

### 7.3 特性

- **append 模式**：断点续训只追加新行，不重写历史
- 表头自动检测
- 通过 `atexit` 注册 flush
- 单文件单任务，不引入 DB
- 可用 Excel / pandas / CSV 库直接画训练曲线

### 7.4 示例：分析 A4 训练

```python
import pandas as pd
df = pd.read_csv("logs/training_history/A4.csv")
df.plot(x="epoch", y=["train_loss", "val_loss"])
df.plot(x="epoch", y="lr")  # 看 LR 调度
```

## 九、故障排除

### Q: 任务显示 `🔒` 但依赖已完成？

检查 `checkpoints/{variant}/{subdir}/` 目录下是否有对应的 `e{N:03d}_best.pt`，且 `is_complete=True`（可用 `verify_checkpoints.py` 验证）。

### Q: 续训时显示 `Epoch 1/150` 但加载了 `e008_last.pt`？

`train_model` 没接 `start_epoch` 参数——v4.6.10 修复，详见 [架构设计文档 §8.3](../architecture/架构设计文档.md#83-续训流程)。

### Q: 续训时不保存 `e{N+1}_last.pt`？

`last_checkpoint_path` 推断只处理 `_best.pt` 结尾，v4.6.10 已修复。

### Q: 续训第一个 epoch 瞎刷 best？

`best_loss=inf` 不继承历史，v4.6.10 已透传 `best_loss`。

### Q: 已跑完的任务被识别为"待执行"反复跑？

老检查点的 `task_id` 字段（如 `'A4_long'`）不在 `all_tasks` 中——v4.6.11 的 fuzzy match 应已认主。如仍出现，参考 [CODE_BUGS.md B008](../CODE_BUGS.md)。

### Q: 训练中途想跳过？

在自动执行模式下，输入 `n` 可以跳过当前失败任务继续下一个。

### Q: 硬件等级显示不正确？

确保 CUDA 驱动正常，显存计算可能包含其他进程占用。

### Q: 导入的检查点没有自动识别？

检查文件名是否符合新格式 `{task}_off{offset}_e{N}_{kind}.pt`，或检查点是否包含 `task_id` 元数据。导入路径见 §四。

### Q: 提示"文件名、目录名或卷标语法不正确"？

v4.6.10 已修复。`team_train.py` 用 `subprocess.run(shell=False)` 调子进程，不会触发 cmd.exe 路径转义问题。如直接调 `os.system` 自定义脚本，需要路径加双引号。
