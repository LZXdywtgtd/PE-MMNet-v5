# 快速配置指南

> PE-MMNet v4 首次使用必读 | 10 分钟快速上手

---

## 一、环境准备

### 1.1 硬件要求

| 硬件 | 最低配置 | 推荐配置 |
|------|----------|----------|
| GPU | 4 GB 显存 | 8 GB+ 显存 |
| 内存 | 8 GB | 16 GB |
| 存储 | 10 GB | 20 GB+ |

GPU 环境装法见 [CUDA 安装指南](CUDA安装指南.md)。

### 1.2 Python 环境

要求 Python 3.8+：

```bash
python --version
```

推荐使用 conda（`pe_mmnet` 环境）：

```bash
conda create -n pe_mmnet python=3.10
conda activate pe_mmnet
```

### 1.3 安装依赖

```bash
cd project_v4
pip install -r requirements.txt
```

核心依赖：
- `torch`（GPU 版，见 CUDA 指南）
- `timm>=0.9.0` —— Swin/ViT 预训练
- `scipy`
- `numpy`, `pandas`
- `Pillow`

### 1.4 验证安装

```bash
python -c "import torch; print(f'PyTorch: {torch.__version__}'); print(f'CUDA: {torch.cuda.is_available()}')"
```

预期：CUDA: True（GPU 机器）或 False（CPU 机器，功能仍可跑）。

## 二、数据准备

### 2.1 数据目录结构

**文件夹名称无所谓，代码会自动扫描！**

```
data_root/
├── 实验A/
│   ├── 温度/d001.png, d002.png, ...     # 温度场图像（必须）
│   ├── 应力/d001.png, d002.png, ...     # 应力场图像（必须）
│   ├── 表格/Table_表面最大值.csv          # 标签数据（可选）
│   └── d_hist/d001.png, d002.png, ...   # 分割掩膜（可选）
└── 实验B/
    ├── 温度/x001.png, x002.png, ...
    └── 应力/x001.png, x002.png, ...
```

| 文件夹 | 必须 | 说明 |
|--------|------|------|
| `温度/` | ✔ | PNG 灰度图像 |
| `应力/` | ✔ | PNG 灰度图像 |
| `表格/` | ✗ | CSV 标签文件 |
| `d_hist/` | ✗ | 分割掩膜图像（仅 segmentation 任务需要） |

`get_data_batches()` 只把含 `表格/` 且其中有特定 CSV 文件（`参数化扫描-表面最大值.csv` / `Table_表面最大值.csv` / `Table_Crack.csv` / `Table_Hist.csv`）的子目录识别为数据批次。

### 2.2 配置数据路径

**自动配置（推荐）**：首次运行 `train_launcher.py` 会自动提示配置。

**手动配置**：在 `project_v4/` 根创建 `config.json`：

```json
{
  "data_root": "D:\\你的路径\\参考输入"
}
```

> `config.json` 字段：必填 `data_root`，可选 `output_dir` (默认 `./output`)、`checkpoints_dir` (默认 `./checkpoints`)、`results_dir` (默认 `./benchmark_results`)。

## 三、快速开始

### 3.1 团队协作（推荐新手）

最简单的训练方式：

```bash
python team_train.py
```

菜单中选择任务编号即可开始训练。详细说明见 [团队协作训练指南](../collaboration/团队协作训练指南.md)。

### 3.2 交互式启动

```bash
python train_launcher.py
```

图形菜单，可选变体、参数、批次。

### 3.3 直接训练

```bash
# 基线模型（推荐首次使用）
python run_train.py --mode train --variant resnet18 --epochs 150

# Swin-YOLO（需要预训练权重，默认 lr=1e-4）
python run_train.py --mode train --variant swin_yolo --epochs 150

# ViT-YOLO（需要预训练权重）
python run_train.py --mode train --variant vit_yolo --epochs 150

# DETR（需要预训练权重）
python run_train.py --mode train --variant detr --epochs 150

# Swin-YOLO + PatchTST 时序骨干
python run_train.py --mode train --variant swin_yolo_patchtst --epochs 150
```

> `team_train.py` 内部用 `subprocess.run(args, shell=False)` 调子进程，不走 cmd.exe，不会出现"文件名语法不正确"错误。

## 四、模型变体选择

| 变体 key | 架构 | 显存 | 推荐场景 |
|----------|------|------|----------|
| `resnet18` | ResNet-18 + Cross-Attention | ~2 GB | 新手首选，快速验证 |
| `swin_yolo` | Swin-Tiny + YOLO-FPN | ~4 GB | 空间定位精度要求高 |
| `vit_yolo` | ViT-Small + YOLO-FPN | ~3 GB | 全局注意力需求 |
| `swin_yolo_patchtst` | Swin-Tiny + YOLO-FPN + PatchTST | ~4 GB | 长程时序依赖 |
| `detr` | ResNet-18 + Transformer | ~5 GB | 全局上下文感知 |
| `1d_only` / `2d_only` / `concat` / `add` / `cross_attn` | 消融变体 | ~1-2 GB | 消融实验 |

10 个变体都在 `run_train.py` 的 `--variant` choices 中。详细架构见 [架构设计文档](../architecture/架构设计文档.md)。

## 五、高级参数

### 5.1 融合方式

```bash
# 交叉注意力融合（默认）
python run_train.py --variant resnet18 --fusion cross_attn

# 门控融合（温度/应力分治）
python run_train.py --variant resnet18 --fusion gated
```

> `--fusion` 只接受 `cross_attn` / `gated` 两个值。

### 5.2 注意力模块

```bash
# 坐标注意力（保留位置信息，所有变体均支持）
python run_train.py --variant resnet18 --use_coord_attn
python run_train.py --variant swin_yolo --use_coord_attn
```

### 5.3 分阶段训练

```bash
python run_train.py --variant resnet18 --staged_train --epochs 150

# 自定义短序列批次
python run_train.py --variant resnet18 --staged_train --short_batches 单次扫描 参数化扫描1
```

### 5.4 数据增强

```bash
# ThermalCutMix（物理安全版，仅作用于温度通道）
python run_train.py --variant resnet18 --aug_cutmix_prob 0.3
```

### 5.5 三通道时序输入

```bash
# 使用 [初始温度, 当前温度, 温度变化率] 三通道
python run_train.py --variant resnet18 --triple_channel
```

### 5.6 时间偏移预测

```bash
# 预测 1 步后（0.05s 后）的标签
python run_train.py --variant resnet18 --predict_offset 1

# 预测 2 步后（0.1s 后）
python run_train.py --variant resnet18 --predict_offset 2
```

### 5.7 等值线预处理

```bash
# 对参数化扫描4启用等值线去除
python run_train.py --variant resnet18 --remove_contours
```

### 5.8 禁用数据批次

```bash
# 禁用指定批次
python run_train.py --variant resnet18 --disable_batch 参数化扫描4
```

### 5.9 任务模式

```bash
# 检测（默认）
python run_train.py --task detection

# 分割
python run_train.py --task segmentation

# 多任务（检测+分割）
python run_train.py --task multitask
```

## 六、显存配置

`auto_select_config()` 自动按空闲显存选择：

| 空闲显存 | image_size | batch_size | FP16 |
|----------|-----------|-----------|------|
| ≥10 GB | 512 | 16 | ✔ |
| 6-10 GB | 512 | 8 | ✔ |
| 4-6 GB | 384 | 8 | ✔ |
| <4 GB | 256 | 4 | ✗ |

> FP16 仅对 `swin_yolo` / `vit_yolo` / `detr` / `swin_yolo_patchtst` 4 个新变体默认开启，其它变体因 NaN 风险关闭。

**手动指定**：

```bash
python run_train.py --image_size 384 --batch_size 4
```

`--image_size` 接受 256 / 384 / 512 / 768 / 1024（其它值会被拒）。

## 七、常见问题

| 问题 | 解决方案 |
|------|----------|
| `CUDA: False` | 见 [CUDA 安装指南](CUDA安装指南.md) §六 |
| "未找到数据批次" | 检查 `config.json` 中的 `data_root` 路径 |
| Loss 是 NaN | `--lr 1e-4`（已是默认）；如仍 NaN，禁用 FP16（4 个新变体外的） |
| 显存不足 | `--image_size 256 --batch_size 4` |
| 预训练权重下载慢 | 设 `HF_ENDPOINT=https://hf-mirror.com` |
| "文件名、目录名或卷标语法不正确" | 这是 Windows cmd.exe 路径转义问题。`team_train.py` 已用 `subprocess.run(shell=False)` 修复；如直接调 `os.system` 自定义脚本，路径要包双引号 |
| `--lambda_mono` 改了没效果 | 4 个新变体（swin_yolo/vit_yolo/detr/swin_yolo_patchtst）硬编码 lambda_mono=0.1，不读 CLI；只在 6 个旧变体生效（见 [CODE_BUGS.md B003](../CODE_BUGS.md)） |

### 7.1 预训练权重问题（swin_yolo/vit_yolo/detr）

这些变体需要从 HuggingFace 下载预训练权重。

**方法 1：设置镜像站（推荐）**

```bash
# Windows
set HF_ENDPOINT=https://hf-mirror.com

# Linux/Mac
export HF_ENDPOINT=https://hf-mirror.com
```

**方法 2：使用 resnet18 变体（无需预训练权重）**

```bash
python run_train.py --variant resnet18 --epochs 2
```

## 八、训练监控

### 8.1 实时 ETA

每 10 轮显示训练进度盒子（Valid 行超长时会分两行显示）：

```
╔════════════════════════════════════════════════════════════════════╗
║ Epoch 15/150 | Best: 12 | Progress: [████████░░░░░░░░] 10%  ║
╠════════════════════════════════════════════════════════════════════╣
║ Train | Loss: 0.4562 | LR: 3.00e-04 | Time: 1.3s          ║
╠════════════════════════════════════════════════════════════════════╣
║ Valid | R2: 0.8756 (Δ+0.0234) | RMSE: 0.1423 (Δ-0.0012)   ║
║       | MAE: 0.1023 (Δ-0.0056) | 违反率: 38.2% (Δ-2.1%)  ║
╠════════════════════════════════════════════════════════════════════╣
║ System| EMA: 1.3s/epoch | ETA: 2m55s | 完成: 14:32 ±0.2s   ║
╚════════════════════════════════════════════════════════════════════╝
```

说明：
- Valid 行分两行显示时，`(Δ±value)` 为相对上轮的改善值（+ 表示改善）
- System 行显示置信区间（5 轮后开始计算）

### 8.2 检查点保存

路径格式（v4.6.6+）：

```
checkpoints/{variant}/{subdir}/{task}_off{offset}_e{N:03d}_{best|last}.pt
```

示例：

```
checkpoints/detr/baseline/detection_off0_e020_best.pt
checkpoints/detr/baseline/detection_off0_e047_last.pt
```

`{N:03d}` 是 3 位零填充的 epoch 编号。`best` 和 `last` 的 epoch 可能不同（val_loss 没改善时 best 保留之前的）。

### 8.3 训练历史 CSV

按 `task_id` 分文件，append 模式：

```
logs/training_history/{task_id}.csv
```

字段：`timestamp, task_id, variant, subdir, predict_offset, epoch, train_loss, val_loss, best_loss, lr, epoch_time_s`

```python
import pandas as pd
df = pd.read_csv("logs/training_history/A4.csv")
df.plot(x="epoch", y=["train_loss", "val_loss"])
```

## 九、团队协作

### 9.1 组员操作

1. 接收协调者发来的 `tasks/` 文件夹
2. 放入 `project_v4/` 根目录
3. 运行 `python team_train.py`
4. 选择任务编号开始训练

### 9.2 检查点导入

将队友的 `.pt` 检查点复制到 `checkpoints/` 目录。

注意：`import_checkpoint` 会复制到 `checkpoints/` 根目录，不会自动放到 `checkpoints/{variant}/{subdir}/`（见 [CODE_BUGS.md B009](../CODE_BUGS.md)）。如 team_train 找不到，需手动 `mv`。

### 9.3 自动执行

```bash
# 自动执行所有可执行任务
python team_train.py --auto

# 强制执行（包括硬件警告任务）
python team_train.py --auto --force
```

详细使用见 [团队协作训练指南](../collaboration/团队协作训练指南.md)。
