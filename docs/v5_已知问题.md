## V5-011 — 低阈值下 crack_mask 占满 patch

- **状态**：已知
- **位置**：`data/patch_simulator_v5.py` 裂纹提取

## V5-013 — Maxwell 显式 Euler 在 dt > τ/2 时 clip 到 0

- **状态**：已知
- **位置**：`data/viscoelastic.py` update_step
- **现象**：当 dt > τ/2 时显式 Euler 可能振荡，clip 到 0 防止物理失真
- **影响**：大 dt 场景下松弛行为失真（实际应力可能为正的小值，被错误 clip）
- **不修原因**：v5-α MVP 简化处理；可用 implicit Euler 或 analytical 替代（v5-β）

## V5-016 — 仿真预计算占用内存大

- **状态**：已知（v5-α MVP 设计决策）
- **位置**：`data/patch_dataset_v5.py` `PatchDatasetV5._precompute`
- **现象**：`PatchDatasetV5.__init__` 时一次性仿真所有样本到内存 cache。
  每个 256×256 样本约 2MB（3 通道 256×256 float32 + 关键点 + 像素），
  1000 样本约 2GB 内存占用。
- **影响**：大数据集训练时内存压力大；GPU 受限于 CPU 内存而非显存
- **不修原因**：v5-α MVP 简化（仿真一次 ~30s，每 epoch 重新仿真不可接受）。
  v5-β 真实数据接入时改为磁盘缓存（hdf5 / npz）。

## V5-017 — `--fast_thermal` 仅用于测试

## V5-018 — V5A3 coverage_loss 处理空真值像素的策略

- **状态**：已知（v5-α MVP 设计决策）
- **位置**：`training/ordered_kp_loss.py` `coverage_loss`
- **现象**：当 `true_crack_pixels.size(1)=0`（无裂纹像素）时，原实现 `min_per_true.mean(dim=-1)`
  会因空张量返回 NaN，导致训练崩溃。改为返回 surrogate（0 梯度）
- **影响**：训练初期 batch 内所有样本可能都没有裂纹（高阈值 + 短周期），
  loss 仍可正常计算（= 0 梯度），不阻止训练推进
- **不修原因**：v5-α MVP 接受简化处理；v5-β 接真实数据后此分支概率下降

## V5-021：GT 满面退化——阈值化在宽平台应力场上只能产出满面或空（⚠️ P0，v5-α 无法产出有效 GT）

- **状态**：已记录但未修复（2026-09-29 比赛副本回填时确认）
- **代码位置**：`patch_simulator_v5.py` 应力求解 + `crack_stress_threshold_MPa` 阈值化
- **现象**：应力场呈"边界高、中心低"的宽平台——阈值低 → 整个 patch 超阈成面
  （满面），阈值高 → 空集。比赛副本实测（assets th=11，1000 样本）：281 个
  "正样本"中 250 个（89%）裂纹像素占 93.85% 面积，真线状裂纹仅 31 个
- **影响**：v5-α **从未产出过有意义的 GT**。在此 GT 上训练的模型学到的是
  "覆盖全场"或"覆盖空集"，任何 loss 修复都救不了监督目标本身
- **未修原因**：需要仿真器应力场重构（空间场扰动或 Griffith S5 缺陷萌生），
  属于新实验而非 bugfix。修复验证实验已设计：初始温度场注入局部热点
  （5×5 +200℃）→ 看 mask 是否线状
- **验收标准（修复后必须全部满足）**：
  1. 线状裂纹样本占比 ≥ 60%（正样本中面积占比 < 20% 且 elongation > 3）
  2. bbox 中心位置分布不集中于 patch 边界（跨象限覆盖率 ≥ 3/4）
  3. 模型对输入敏感：不同输入的 pred_kpts 跨输入方差 ≥ 1e-3（平台解时 0.0007）
  4. 正样本 chamfer ≤ 真关键点上界 × 1.5
- **教训**：阈值扫描（th→正样本率）**必须同时报告 GT 面积占比分布**，
  只数 n_px>0 会把满面当成正样本（本次事故根因）
